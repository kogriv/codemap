# Гэп R1-C106. Живая функция в отчёте `dead-code`

В аудите потребительского проекта из 41 функции, имя которой встречалось
только в собственном определении, 38 вызывал фреймворк. Среди причин были
декораторы регистрации, валидаторы и методы внешних базовых классов.
У повторных определений с декоратором-фабрикой обе функции могли вызываться
после того, как более позднее определение сменило привязку имени.
[Бэклог, R1-C106](../BACKLOG.md).

R1-C46 сохраняет строки более ранних определений в `extras.shadows` и
показывает их в разделе `Shadowed definitions — certain`. Наличие декоратора
на прежней функции в отчёт не попадает. Декоратор может сохранить объект
функции в реестре при её объявлении. Функция, которую вызвали из реестра,
исполняется даже после смены привязки имени.

R1-C55 учитывает одноимённый метод предка, когда декларация есть в графе.
При внешнем предке декларации метода в графе обычно нет. Тогда приватный
метод подкласса без статических входящих ссылок может оказаться в `high`.

Нужны два синтетических воспроизведения с наблюдаемым вызовом и контрольные
функции без этих признаков. Исторические 41 и 38 описывают исходный аудит.
Повторный замер на его дереве требует доступа к закреплённым исходникам.
[Дизайн и приёмка](../docs/design/registered_definitions_dead_code.md).

**Сверка 24.11.2026.** На синтетике обе регистрации действительно
вызываются. В fast и deep раннее декорированное определение ушло из
однозначных затенений. Вызванное через `argparse` переопределение перешло
из `high` в `medium`, а соседний неиспользуемый метод сохранил `high`.
Повтор исходной выборки 41 → 3 остаётся отдельной проверкой.
[Доказательства приёмки](../docs/design/registered_definitions_dead_code.md#verification-on-m99).
