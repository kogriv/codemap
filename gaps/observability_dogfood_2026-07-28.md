# codemap — обкатка видов на живых вопросах (dogfood) и findings

**Дата:** 2026-07-28
**Тип:** эмпирическая обкатка (dogfooding) + перечень findings
**Вопрос:** держат ли виды M2 (RAG / vault / mermaid) на **живых вопросах о bquant** —
дают ли ответ дешевле, чем чтение исходников, и где граница годности.
**Связано:** `../BACKLOG.md` (M2 сделан, M6 предложен), `../DESIGN.md` (§3 вход, §7 границы,
§10.12 решение по repo-scope), `coverage_gap_analysis_2026-07-24.md` (CM-*).

## 1. Метод

Направили codemap на его собственную мишень (`bquant`), deep-граф (`--deep`, 51 с,
1292 calls-ребра). Прогнали 4 живых вопроса через 3 вида + прямой запрос графа; каждый
ответ сверили с ручным чтением / grep. Вид проходит, если ответ **совпал с ручным и
потребовал меньше шагов**.

Вопросы:
1. Кто продюсит `ZoneAnalysisResult` и кто потребляет?
2. Что зовёт `analyze_zones` и по какой цепочке доходит до детекторов зон?
3. Иерархия индикаторов вокруг `BaseIndicator` / `CustomIndicator`.
4. **Можно ли безболезненно выпилить deprecated `MACDZoneAnalyzer`** — весь ли
   blast radius виден в графе, что останется на grep.

## 2. Что держит

- **Структура внутри пакета точна.** Q3: `BaseIndicator ← {Custom, Library, Preloaded, _Stub}`,
  `CustomIndicator ← {Bollinger, EMA, MACD, RSI, SMA}` — верно и полно.
- **Deep-рёбра помечены `resolution`.** Q2: цепочка `analyze_zones` → детекторы/стратегии
  видна связной, каждый вызов с меткой (module/self/imported/deep).
- **mermaid class/deps корректны и читаемы.** Подсистема `zones`: Protocol-базы стратегий,
  `ZoneAnalyzer <|-- BaseAnalyzer`, детектор-база — сходится с AGENTS.md.
- **vault-wikilinks добротны.** `CustomIndicator.md` несёт Interits/Subclasses ссылками;
  Obsidian Graph View по подсистеме читается.
- **deprecated-флаг на месте**, docstring-миграция (`analyze_zones`-пример) всплыла в RAG.

## 3. Findings (по убыванию важности)

### F1 — 🔴 Слепота по области (доминирующий разрыв)

**codemap индексирует только пакет `bquant/`.** Тесты, доки, `examples/`, `research/`,
`scripts/` — вне анализа целиком. На вопрос «кто использует / можно ли удалить X» реальный
blast radius живёт **в основном вне области**.

Замер на Q4 (`MACDZoneAnalyzer`):

| Источник | Что сказал граф | Что есть на самом деле (grep) |
|----------|-----------------|-------------------------------|
| внутри `bquant/` | 2 вызова из своего модуля (`analyze_macd_zones`, `create_macd_analyzer`) + реэкспорт из `bquant.indicators` | **совпало** — граф внутри пакета точен |
| тесты | — (не видит) | `test_macd_analyzer.py` ×22, `test_macd_backward_compatibility.py` ×15, `integration/test_backward_compatibility.py` ×12, `test_full_pipeline.py` ×6 + ~10 strategy-тестов |
| доки | — (не видит) | `docs/api/indicators/macd.md` ×11, migration guide ×7, README, quick_start… ~15 файлов |
| examples/research/scripts | — (не видит) | `examples/02_macd_zone_analysis.py`, `research/notebooks/*`, `scripts/analysis/*` |

**Вывод:** причина слепоты — **не** потолок резолва вызовов (25.7%, M5), а **однопакетная
область**. Граф не соврал — он ответил на более узкий вопрос («кто внутри пакета»), чем задан
(«кто во всём репо»), и промолчал о границе. Для delete/impact-вопросов это делает инструмент
**практически неприменимым** без grep-подстраховки. → закрывается вехой **M6** (repo scope).

### F2 — 🟠 `query` класса не отдаёт входящих ссылок

CLI `codemap query <Class>` печатает только `bases`/`subclasses`. «Кто меня зовёт / импортирует
/ ссылается» пришлось считать своим скриптом по графу (обход входящих рёбер). Даже в пределах
пакета inbound-references — базовый impact-вопрос — не выведен наружу. → часть **M6** (inbound-refs
в query, сгруппированные по роуту и типу ребра).

### F3 — 🟡 RAG класс-чанк без соседей (гранулярность)

Класс-чанк не агрегирует call-рёбра своих методов. Миграционная связь
`MACDZoneAnalyzer.analyze_complete_modular → analyze_zones` сидит на ребре **метода**; на
гранулярности класса она невидима (спасла docstring, куда человек вписал пример вручную).
897/989 чанков несут `neighbors`, но у классов соседи — только классового уровня
(bases/subclasses/registered_as), без «что зовут мои методы». → доработка `serve/rag.py`:
класс-чанк агрегирует исходящие вызовы своих методов (кандидат, не блокер M6).

### F4 — 🟡 classDiagram не видит registry+Protocol проводку

Конкретные стратегии (`zigzag`/`find_peaks`/`pivot_points`) в classDiagram не появляются: они
не наследуют Protocol (структурная типизация), а цепляются через `@Registry.register`-декоратор.
Диаграмма показывает каркас (Protocol-базы), но не фактическую проводку. Данные есть
(`extras.registry`, M1.5), нет вида. → отдельный «registry-map» вид (кандидат, не блокер M6).

## 4. Вердикт по исходному вопросу (Q4)

**`MACDZoneAnalyzer` выпилить безболезненно нельзя.** Он deprecated с удалением в **v3.0.0**,
за ним стоит **намеренный backward-compat тест-набор** (~20 файлов, сотни ссылок) +
миграционные доки. Удаление = breaking-change задача релиза v3, а не чистка. Само это решение
codemap в текущем виде подсказать **не мог** (F1) — потребовался grep.

## 5. Ключевой вывод для продукта

Самый большой разрыв между «карта пакета» и «применимый инструмент» — **область, а не глубина
резолва**. Граф уже несёт то, чего grep не умеет (типизированные рёбра, транзитивный обход,
скоуп), но пока видит только ядро. M6 (repo scope / impact) расширяет область до потребителей
и доков — тогда impact-анализ становится тем, ради чего граф и строится, а не переизобретением
grep.
