# Гэп: `review` на правке документации не называет изменённые страницы

**Дата:** 2026-11-06. **Источник:** bquant, первая проба `review` на 0.0.32. **Статус:** ✅ закрыто 2026-11-06 (0.0.33); дизайн —
[`docs/design/review_docs.md`](../docs/design/review_docs.md), бэклог R1-C89.

## 1. Что показали

bquant `cf039ef` правит только `docs/api/analysis/*.md` и трейслог. Граф собран с `--docs docs`. codmap 0.0.32:

```
**0 changed symbol(s)**
_Unresolved hunks (lines outside any symbol): 3 — inspect manually._
_1 non-Python file(s) …: changelogs/…_          ← назван только трейслог
```

## 2. Почему так

Страница документации — узел `kind: doc` с `id` = путь файла, без строк (`lineno` нет), и создаётся она, только
если упоминает символы ядра (`_scan_doc_file`). R1-C87 нашёл её файл в графе, поэтому файл «размещён». Но
`symbols_in_range` ищет определения с диапазоном строк и узел модуля, а у страницы нет ни того, ни другого. Её
хунки падают в `unresolved_hunks`, где по смыслу R1-C87 лежат строки кода вне символов.

## 3. Чем это опасно

Ответ выглядит так, будто что-то не удалось разобрать («inspect manually»), а на деле правка распознана
полностью. Граф знает, какие символы описывает страница, но не говорит этого. Правка документации — повод
проверить, что страница всё ещё говорит правду о коде, и этот повод теряется.
