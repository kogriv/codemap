# Гэп: точка входа определена так, что у библиотеки её не бывает — и чем лучше резолвинг, тем пустее ответ

**Дата:** 2026-09-10. **Источник:** сессия bquant, [codemap#19](https://github.com/kogriv/codemap/issues/19),
на следующий день после 0.0.16 — они проверяли **наш** замер из
[bquant#120](https://github.com/kogriv/bquant/issues/120) на своём дереве и воспроизвели его только на
том тире, на котором его делали мы. **Статус:** воспроизведено; решения — §6.

**Одним сообщением пришли три находки.** Первая — заявленный дефект (§1–§4). Две других (§5) —
попутные, и обе про то же самое: **сужение, которое сделали мы сами, обязано себя называть.**

---

## 1. Что они показали

Один символ, одно дерево (`bquant@3591f83`), одна версия (`codmap==0.0.16`), две сборки одной командой,
отличие только `--deep --repeat 3`:

```
fast:  ### Flows reached (1 of 285 entry point(s) in root `core`)
       - ZoneAnalysisPipeline.run — step 3
deep:  ### Flows reached (0 of 252 entry point(s) in root `core`)
       _No entry point reaches it within 5 step(s)._
```

`--flow-depth 6` не меняет ничего. Их таблица входящих `calls` по цепочке:

| узел | fast, in | deep, in |
|---|---|---|
| `ZoneAnalysisPipeline.run` | **0** | 1 (`ZoneAnalysisBuilder.build`) |
| `ZoneAnalysisBuilder.build` | **0** | 1 (`presets._finish`) |
| `presets.analyze_macd_zones` | 43 | 43 — **все** из `tests`/`examples`/`scripts`/`research` |

Полная цепочка в графе есть и обходится руками:
`analyze_macd_zones → _finish → build → run → _run_without_cache → _prepare_data → calculate_atr`.

## 2. Механизмов два, а не один — замерено у себя

Их дерево собрано с потребительскими корнями, наше в §1-замере — нет, и это разводит два независимых
эффекта, которые в их прогоне сложились в один ноль.

**(а) Межкорневая входящая степень убивает голову.** `entry_points` требует `in_degree == 0`, а
`in_degree` считает **все** входящие рёбра, независимо от корня вызывающего. У `analyze_macd_zones` 43
вызывающих, и все 43 — из `tests`/`examples`/`scripts`/`research`. То есть публичная функция, которой
пользователь входит в пакет, перестаёт быть точкой входа именно потому, что её кто-то использует.
Внутри пакета её не зовёт никто — а это и есть признак публичного API, а не признак недостижимости.
Воспроизводится только на repo-scoped сборке.

**(б) Дорезолвливание удлиняет цепочку.** На нашем package-only fast-графе замерено:

```
dist(run) = 3            run — точка входа (build → run не разрешён)
dist(build) = None       цепочка выше run на fast разорвана
dist(analyze_macd_zones) = None
```

На deep `build → run` резолвится, `run` теряет статус входа, а голова оказывается на расстоянии 6 —
дальше умолчания `--flow-depth 5`. То есть даже без потребительских корней ответ на deep беднее, и
только `beyond_depth` мешает ему стать молча пустым.

**Итог:** чем полнее граф, тем меньше множество точек входа. Это свойство определения, а не тира, и
на fast оно работало **случайно** — непорезолвленный вызов оставлял `run` выглядящим входом.

## 3. Почему формулировка неверна

`_No entry point reaches it within N step(s)._` не различает две разные пустоты — ту же пару, которую
проект сам развёл в R1-C44 для `resolved.found`:

1. символа нет ни на одном пути — **это ответ**;
2. голова его пути — публичный API, который по устройству зовут только снаружи, — **это не ответ, а
   следствие нашего определения**.

Для библиотеки второй случай — норма. Одиннадцатое применение «`unknown` ≠ `none`» и первое, где
неизвестна не пустота данных, а **пригодность собственного определения**.

## 4. И наша нота предупреждала только в одну сторону

Нота отчёта (R1-C40/D4) говорит: «непорезолвленный вызывающий оставляет настоящую внутреннюю функцию
выглядящей входом, поэтому знаменатель — верхняя оценка». Обратное следствие — что дорезолвливание
**убирает** вход и обнуляет **числитель** — не названо, а именно оно тут и сработало. Формулировка
их, и она точнее нашей.

## 5. Две попутные находки из того же письма

**(а) Фильтр по степени отвечает пустотой, которая не говорит, что она — фильтр.** Они добрали замер,
которого у нас не было: по 25 целям, до которых достаёт разворачивание реестра, все входящие вызовы
по степеням — **221 `exact` / 1 `inferred` / 49 `heuristic`**, и **у 13 целей из 25 ноль
`exact`-вызывающих**. Эти 13 — не выборка, это **все** методы стратегий (`.calculate`,
`.calculate_global`, `.aggregate_for_zone` у трёх свинговых плюс shape/divergence/volume/volatility).
Значит `callers(symbol, min_confidence="exact")` на методе стратегии отдаёт `[]`, и это `[]`
неотличимо от «никто не зовёт», хотя зовут — через объект, выданный фабрикой по строковому имени.

Это R1-C28 ровно в той же форме, только про фильтр вместо лимита: **сужение обязано объявляться
всегда, включая случай, когда оно ничего не отбросило.** Поверхность моя, ей два дня, и она приехала
без этого объявления.

**(б) `diff` считает изменением API публичные символы потребительских корней.** У них
`diff v0.0.16 → main` (обе стороны deep) дал «No breaking changes, 47 added», и **40 из 47** — функции
тестов. Вопрос был задан прямо: задумано ли так, потому что от этого зависит, годится ли `--exit-code`
как релизный гейт. Замерено по коду: `diff_api` фильтрует **только** по `visibility == "public"`
(`codemap/apidiff.py:183`), никакого условия на `extras.root` там нет. Значит на repo-scoped графе
гейт управляется правками тестов, а не пакетом. Не задумано — дефект.

## 6. Решения

Дизайн: [`docs/design/flow_reach.md`](../docs/design/flow_reach.md) §9 (D7–D9),
[`docs/design/edge_resolution.md`](../docs/design/edge_resolution.md) §9 (D7),
[`docs/api-diff.md`](../docs/api-diff.md). Бэклог: **R1-C50** (§1–§4), **R1-C51** (§5а),
**R1-C52** (§5б).

- **D7 — точка входа считается по своему корню.** `in_degree` внутри корня, а не по всему графу:
  вызов из `tests` — это потребитель, а не внутренний вызывающий. Публичный API снова становится
  головой потока, и определение перестаёт зависеть от того, кто пакет использует.
- **D8 — вход говорит, чем он подтверждён.** У точки входа перечисляются вызывающие из других корней
  (`external_callers: {tests: 43, ...}`): это не шум, а доказательство, что голова — публичная.
- **D9 — пустота называет свой род**, и нота предупреждает в обе стороны (§4).
- **D7-C51 — фильтр объявляет себя** так же, как лимит: сколько отброшено и по каким степеням.
- **C52 — `diff` судит только корень пакета** и говорит, сколько символов не судил.
