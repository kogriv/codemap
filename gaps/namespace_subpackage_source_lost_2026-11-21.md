# Гэп: у модулей namespace-подпакета нет исходного текста, и импорты внутри функций теряются

**Дата:** 2026-11-21. **Источник:** приёмка R1-C108 (E4) на клоне проекта C: правило `allowed`, собранное из
графа, разошлось с независимым AST-подсчётом на 16 пар слоёв. Все 16 начинаются в трёх приложениях без
`__init__.py`. **Статус:** ✅ закрыто 2026-11-21 (0.0.39); дизайн — [`docs/design/namespace_source.md`](../docs/design/namespace_source.md),
бэклог R1-C109 (закрывает и R1-C105).

## 1. Что показали

Воспроизведение, 5 файлов: `p/__init__.py`, `p/reg/__init__.py`, `p/reg/t.py` (`def g()`), `p/nsp/m.py` без
`__init__.py` в `p/nsp/`:

```python
def f():
    from p.reg.t import g
    return g()
```

`codemap build p` (0.0.38 и dev): модуль `p.nsp.m` есть, вызов `h → f` есть, ребра `imports p.nsp.m → p.reg.t`
нет. На проекте C — 46 модулей в трёх приложениях; потеряны все их импорты внутри функций (в `apps.ready()`,
внутри `if` в теле функции), 16 пар слоёв.

## 2. Почему так

- **(a) Пустой исходник.** R1-C94 D1 читает namespace-подпакеты через `griffe.visit` и передаёт ему
  `lines_collection`. Но `griffe.visit` текст туда не кладёт, это делает загрузчик griffe
  (`loader.py:664`, `self.lines_collection[module_path] = code.splitlines()`). Поэтому `module.source`
  пустой. Проход импортов R1-C29/C48/C68 (`_source_import_targets`) читает именно `module.source` и молча
  ничего не находит. Слой вызовов читает файл с диска сам, поэтому вызовы видны.
- **(b) Миграции не читаются.** Обход namespace-подпакета пропускает файлы, чьё имя не идентификатор
  (`0001_initial.py`). griffe в обычном пакете такие файлы грузит: фильтра у него нет, `finder.py`
  `iter_submodules`. Каталог с `__init__.py` внутри namespace-приложения
  (`coverage/migrations/`) теряет такие модули с пометкой `unread`. Гипотеза R1-C105 (совпадение имени с
  coverage.py) неверна: в том же дереве 15 обычных приложений с теми же именами миграций читаются.

## 3. Чем это опасно

Молчаливый неполный граф там, где он должен быть полным. Гейт `allowed` и `forbidden` не видит новое ребро из
импорта внутри функции в namespace-подпакете. `report architecture` недосчитывает ленивые циклы, `impact`
недосчитывает зависимых. Для (b) предупреждение `unread` есть, но с неверным объяснением.
