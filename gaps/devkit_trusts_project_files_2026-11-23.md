# Гэп: devkit исполняет и пишет то, что лежит в файлах проекта

**Дата:** 2026-11-23. **Источник:** внешний аудит (F-01, F-02, F-09), воспроизведено здесь маркером.
**Статус:** ✅ закрыто 2026-11-23 (0.0.46), бэклог R1-C121. Advisory
[GHSA-c3hp-596c-2p77](https://github.com/kogriv/codemap/security/advisories/GHSA-c3hp-596c-2p77) (high, затронуты
0.0.39–0.0.45), опубликован 2026-11-23. **Обход исправления** найден повторным аудитом (FU-01), закрыт R1-C133 —
раздел 4; advisory [GHSA-mjvh-v399-r45r](https://github.com/kogriv/codemap/security/advisories/GHSA-mjvh-v399-r45r) (high, 0.0.46,
исправлено в 0.0.47).

## 1. Что показали

devkit (R1-C108, 0.0.39) хранит своё состояние в `.codemap-devkit.json` — файл коммитится — и пин codemap в
`.mcp.json`. Оба файла приходят с репозиторием, то есть от того, кто последним запушил. Три пути от них к
исполнению или записи:

1. **Команда из `.mcp.json` исполняется.** `devkit status` и `devkit update` брали пин из `.mcp.json`, если в
   состоянии записан хэш MCP-записи — проверялось наличие хэша, не совпадение. Дальше `pin_version` запускал
   `[*pin, "--version"]`, а `pin_has_mcp` — интерпретатор из shebang файла пина. Проба: пин
   `/bin/sh -c "touch MARKER"` — маркер появляется после `status` и после `update`.
2. **`update` закрепляет эту команду.** Пин, который `update` сохраняет, рендерится в хук post-commit (`C=…`),
   и команда идёт на каждом коммите — не разовое, а постоянное исполнение.
3. **Пути из состояния не проверялись.** `agents_file`, `graph`, `package`, корни шли в `root / value`. Проба:
   `agents_file: "../outside-AUDIT.md"` — `update` пишет файл вне репозитория. То же через символическую ссылку.
4. **Шаблоны не экранировали значения.** `{{package}}`, `{{graph}}` подставлялись в shell хука и в YAML-строки
   CI как есть; `build_args` был через `shlex.join`, а они — нет.

Плюс найденное при разборе: запасной пин `python -m codemap` ставит рабочий каталог первым в `sys.path`, а хук
идёт в корне репозитория — пакет `codemap/`, закоммиченный туда, был бы тем, что выполняется.

## 2. Исправление (0.0.46)

- **Пин** (`install.pin_problem`): принимаются только формы, которые devkit пишет сам — абсолютный путь к
  консольному скрипту `codemap`, или абсолютный python как `-I -m codemap`. Файл должен существовать и не быть
  файлом репозитория (`git ls-files`). Непринятый пин не запускается и не сохраняется; нота называет причину,
  вместо него — этот codemap. Неотслеживаемый `.venv` внутри корня — допустим.
- **Запасной пин** — `python -I -m codemap`: без рабочего каталога в `sys.path`. Старый `python -m codemap`
  при `update` заменяется с нотой.
- **Пути** (`state.path_problem`): относительный, без `..`, внутри корня после разрешения ссылок, из алфавита
  `[A-Za-z0-9._/@+-]`. Состояние с иным путём отвергается целиком (`StateError`, код 2) до любой записи и
  любого запуска; то же для путей из командной строки (`--package`, `--consumer`, `--docs`, `--agents-file`).
  Хуки Claude Code (`brief`, `touched`) при отвергнутом состоянии берут умолчания, а не падают.
- **Шаблоны**: shell и YAML получают `package_sh`/`graph_sh`/`graph_next_sh` — `shlex.quote`. Для обычных
  путей вывод байт в байт прежний. Это вторая стена: первая — проверка алфавита.

Тесты: `tests/test_r1c121_devkit_trust.py` — маркеры, каждая защита снята по отдельности и роняет свой тест.

## 3. Чего это не закрывает

`.mcp.json` сам по себе — команда, которую Claude Code запускает, когда пользователь доверяет серверам проекта.
Это решение клиента и пользователя; codemap отвечает за то, что запускает и пишет он сам.

## 4. Обход: ссылка, которую несёт репозиторий (FU-01, R1-C133)

Повторный аудит 0.0.46 нашёл обход пункта «не файл репозитория»: `_tracked` спрашивал git о пути **после**
`resolve()`. Закоммиченная ссылка `tools/codemap → /bin/sh` раскрывается наружу, и git отвечает «не наш». Имя
`codemap` проходило, `is_file()` проходил. Воспроизведено здесь целиком: `update` записал ссылку в хук, коммит
выполнил закоммиченный `build`. Условие атаки: `.mcp.json` должен назвать абсолютный путь checkout жертвы.

Исправление:

- git спрашивается о пути как он написан и о каждом каталоге на нём, до раскрытия ссылок;
- консольный скрипт принимается по содержимому (`codemap.cli`), а не по имени;
- вне git-репозитория пин внутри корня отвергается.

Тесты — `tests/test_r1c133_pin_links.py`, включая запуск настоящего хука.

Почему это прошло мимо R1-C121: тест проверял закоммиченный **обычный файл**, то есть форму атаки, а не её класс.
