# Гэп: сборка от корня репозитория теряет подпапки без `__init__.py` и огрубляет flat-импорты

**Дата:** 2026-11-10. **Источник:** R1-C94, проверка посылки из замера R1-C93 (RepoBench). **Статус:** ✅ закрыто
2026-11-10 (0.0.38); дизайн — [`docs/design/root_builds.md`](../docs/design/root_builds.md), бэклог R1-C94.

## 0. Что было неверно в исходной постановке

R1-C93 записал, что codemap «не строит вообще» репозитории без обычного пакета. Это не проверялось: отсев A3
делал харнесс замера, который собирал только обычный пакет вокруг файла. Проба 2026-11-10: 12 случайных
репозиториев из отсеянных по A3, `codemap build <корень репозитория>`. Все 12 собрались с кодом 0, по 1–31 с.
Золотой кандидат RepoBench нашёлся узлом в 34 строках из 37, модуль самого файла — в 31 из 37. Корень без
`__init__.py` codemap собирает как namespace-цель с flat-выводом (`docs/flat-layout.md`).

Проба нашла две настоящие дыры.

## 1. Подпапка без `__init__.py` внутри обычного пакета пропадает

`TAOISM/python/` — обычный пакет, а `python/layers/` — без `__init__.py`. Python 3 импортирует
`python.layers.activation` (namespace-подпакет, PEP 420). codemap пропустил все 22 файла `layers/` с причиной
`unread`. Минимально:

- `pkg/__init__.py`, `pkg/layers/act.py` (`def act()`), `pkg/net.py` (`from pkg.layers.act import act`, вызов
  `act()`).
- `python -c "import pkg.layers.act"` работает.
- `codemap build pkg`: `[warning] 1 input file(s) produced no module (1 unread): pkg/layers/act.py`. Узлов
  `pkg.layers*` нет, вызов `act()` не разрешён, импорт указывает на `pkg`.

**Почему.** Griffe пропускает такие каталоги намеренно, это решение апстрима: в комментарии `_load_submodule`
автор считает namespace-подпакет внутри обычного пакета ошибкой пользователя и чаще каталогом скриптов. codemap
унаследовал это молча. Предупреждение `unread` честное, но модуль теряется.

## 2. Flat-импорт с точкой указывает на верхний модуль, а не на импортированный

Корень `repo/` без `__init__.py`, рядом `main.py` и `engine/dataset.py`. `from engine.dataset import get` в
`main.py` даёт ребро `imports repo.main → repo.engine`, а не `→ repo.engine.dataset`. Вызов `get()` при этом
разрешается верно (`calls … → repo.engine.dataset.get`, `imported`). Связность модулей, `impact` по модулю и
слои видят зависимость от пакета, а не от модуля. На `genome` из 37 таких импортов точный модуль получил 1, на
`TAOISM` 0 из 212.

**Почему.** `_flat_sibling` проверяет, что первый сегмент цели — сосед импортирующего модуля, и возвращает этот
первый сегмент. Самый глубокий известный модуль пути он не ищет: R1-C21 писали под голые имена (`from alpha
import X`).

## 3. Чем это опасно

(1) — модули и их вызовы отсутствуют в графе, а `dead-code`, `impact` и `tests` об этом знают только как о
`unread`. (2) — граф правильный по вызовам и грубый по импортам: контракт слоёв и связность считаются по
пакету-родителю. У bquearch в графе `shared` 261 flat-ребро импорта, так что (2) касается соседа.
