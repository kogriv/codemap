# Гэп: манифест скоупа описывает не тот набор файлов, из которого построен граф (issue #15)

**Дата:** 2026-09-02. **Источник:** вторая реальная мишень,
[codemap#15](https://github.com/kogriv/codemap/issues/15) — репорт заведён рядом с
подтверждением починки R1-C36 как **отдельный пункт**, который этой починкой не закрывается.
**Статус:** открыт, кандидат **R1-C41**. **Замерено на 0.0.7** (`daeb7f0`, fast tier).

## 1. Что репортовали

Репортёр воспроизводил у себя R1-C36 (сборка могла проанализировать чужой пакет с тем же
именем): в пустой каталог положен подставной модуль, сборка направлена на их дерево из 47
`.py`. На 0.0.4 граф нёс **48** файлов, на 0.0.5 — 47, починка подтверждена. Наш
`module_count_diagnostic` при этом **сработал** и сказал ровно то, что должен был.

Молчало другое:

> **Манифест `graph.json.meta.json` подставной файл не перечислял.** Сайдкар описывал 47 файлов
> (с `git_blob` и `sha256` на каждый), граф нёс 48. Артефакт, который потребитель читает, чтобы
> ответить «что именно проанализировано», отвечал неверно и без единого признака.

Их предложение — проверять не только счёт, но и **принадлежность**: у каждого узла-модуля `file`
обязан резолвиться в путь, перечисленный в `scope.files`.

Плюс честный отрицательный результат с их стороны, сужающий радиус: вариант «тень» (файл с
именем из их дерева и чужим содержимым) замещения **не** дал — на namespace-пакете радиус R1-C36
это «лишние модули», а не «подменённые».

## 2. Дефект шире репорта: та же дыра открывается без всякой подставы

Репорт описывает сценарий с подставным каталогом. Замер показывает, что тот же разрыв
воспроизводится на **обычном дереве, без атаки и без R1-C36** — двумя способами, которые
случаются в рабочий день.

Синтетический репозиторий: `pkg/__init__.py` и `pkg/core.py` под git, `.gitignore` содержит
`pkg/generated_*.py`.

| что положено в пакет | в графе | в `scope.files` | `scope_id` двигается | что сказал тул |
|---|---|---|---|---|
| правка отслеживаемого файла | да | да | **да** | — (контракт работает) |
| **untracked** новый модуль (`git add` ещё не делали) | да | **нет** | **нет** | только `git.dirty_files` называет его как `??` |
| **gitignored** модуль (`generated_version.py`) | да | **нет** | **нет** | **ничего** |
| то же дерево без git (fs-режим) | да | да | да | — (совпадение по построению) |

Два графа, отличающиеся содержимым (во втором есть символ `newly_added`, которого нет в первом),
пришли с **одинаковым** `scope_id` — `sha256:2b1dc442aadbe1f1e00…`. Идентичность входа, ради
которой M19.A и заводилась, у этих двух сборок совпала при разном входе.

`module_count_diagnostic` здесь молчит **правильно**: `inputs.python_files` = 3 и модулей в графе
3 — экстрактор прочитал три файла и построил три модуля, закон сохранения соблюдён. Расходится
с ними только манифест, а его в этом сравнении нет.

### 2.1 Это не отчётность, это кэш

`scope_id` — не описание, он ключ. Замер на том же дереве:

```
$ codemap build pkg --incremental -o inc.json
[incremental] unchanged: 0 module(s) recomputed
$ python -c "... 'third_symbol' in graph ..."
False
```

Файл на диске изменён и определяет новый символ; инкрементальная сборка сообщила
«ничего не изменилось» и отдала прежний граф как актуальный. Тот же ключ читает `watch`
(`ScopeProbe` сравнивает `scope_id`) — **этот путь я не запускал**, вывод сделан по коду.

И третье следствие — то, которым репортёр закрывал у себя вопрос доверия к графу: сверка
`git_blob`/`sha256` из сайдкара с деревом («все 329 файлов совпали, 0 расхождений»). Метод
корректен **для перечисленных файлов**; неавторитетно само перечисление.

## 3. Причина: два независимых определения слова «вход»

- **Манифест** (`codemap/scope.py`, `resolve_scope`) в git-режиме перечисляет вход через
  `git ls-files` — то есть **отслеживаемый набор**.
- **Экстрактор** обходит **файловую систему**.

В fs-режиме обе стороны обходят одно и то же, и расхождения нет по построению (замерено: 4 = 4).
В git-режиме это два разных множества, и **ничто их не сравнивает**. `include` в git-режиме
применяется как фильтр *после* `git ls-files` (`scope.py:142`), поэтому он может только убрать
файл из манифеста и никогда не может добавить.

Дизайн это ограничение **знал** и делегировал его несуществующему механизму —
[`docs/design/scope.md` §1.5](../docs/design/scope.md):

> git mode only covers tracked files (untracked/generated files enter via the spec's `include`)

Спека с `include`-оверлеем — это Feature B (исследовательская обвязка R2); у продуктового
`resolve_scope` такого входа нет. Люк, названный в дизайне, не прорезан, а дыра под ним молчит.

Там же — утверждение, которое замер опровергает:

> A **dirty** tree is still exact: our sha-256 captures the actual working-tree bytes

Точно — для **изменённых отслеживаемых** файлов (проверено: `scope_id` двигается,
`2b1dc442…` → `43ff83dc…`). Для неотслеживаемых и игнорируемых — нет: они не входят в манифест
вообще, и «dirty» про них знает максимум `dirty_files`.

## 4. Насколько это бьёт сейчас

**Ни разу.** Игнорируемых или неотслеживаемых `.py` внутри анализируемых корней сегодня нет ни у
нас, ни на догфуд-мишени:

```
git status --ignored --porcelain -- bquant | grep -c '\.py$'   → 0
git status --ignored --porcelain -- codemap tests | grep -c '\.py$' → 0
```

Дефект латентный. Это довод за приоритет, а не против починки: он открывается ровно в тот момент,
когда разработчик создал модуль и ещё не сделал `git add`, — то есть в самом обычном состоянии
дерева во время работы.

## 5. Здоровая база: сколько стоит проверка принадлежности

Прямое направление (у каждого узла `file` обязан быть в `scope.files`) на чистых сборках
0.0.7 — **ноль исключений**, включая узлы-доки:

| сборка | файлов в манифесте | узлов-модулей | различных файлов у **всех** узлов | не в манифесте |
|---|---:|---:|---:|---:|
| `build codemap` | 51 | 51 | 51 | **0** |
| `build codemap --consumer tests --docs docs` | 187 (core 51 / tests 112 / docs 24) | 161 | 164 | **0** |

То есть у проверки нет бюджета ложных срабатываний, который пришлось бы обсуждать: она либо
молчит, либо нашла настоящее расхождение. Это тот же класс, что закон сохранения из R1-C23, —
не эвристика с порогом, а доказуемо неверное состояние.

**Обратное направление проверкой быть не может.** На той же репо-сборке 23 файла манифеста не
дали ни одного узла: 21 `.md` из `docs/` (индексируются как ссылки, узел-док рождается не у
каждого), один `.md` под `tests/` и `tests/fixtures/hardpkg/bom.py` — фикстура, намеренно
нечитаемая. Это законный шум; питонья часть обратного направления уже покрыта
`unread_inputs_diagnostic`.

**Симлинк-цикл проверку не ломает:** `pkg/loop -> ../pkg` даёт `inputs.aliased_modules`
(`pkg.loop same_as pkg`), взрыва нет, все файлы в манифесте — 0 нарушений.

## 6. Решение

Три части, намеренно раздельные — они про разные вещи.

**D1 — манифест обязан перечислять то, что будет прочитано, а не то, что помнит git.**
В git-режиме к `git ls-files` добавляется `git ls-files --others --exclude-standard` — ровно тот
набор, который встал бы в индекс от `git add .`. Записи получают `sha256`/`bytes`/`role` как все
остальные, `git_blob` у них нет (его неоткуда взять), и они несут маркер `tracked: false`, чтобы
потребитель отличал «есть в дереве» от «есть в коммите». Следствие намеренное: `scope_id`
становится чувствителен к неотслеживаемому исходнику — именно этого и требуют от ключа кэша.
Цена измерена: `git ls-files --others --exclude-standard` на дереве мишени — **4 мс** против 2 мс
у обычного `ls-files`.

*Отвергнуто:* перечислять вход чисто обходом файловой системы. Это выбрасывает
gitignore-корректность, ради которой git-режим и введён (O6): случайный `venv_*` снова начал бы
менять скоуп — ошибка, на которой пилот и споткнулся.

**D2 — принадлежность как проверка, а не как доверие** (предложение репортёра, остаётся в силе
и после D1). После D1 закрыта дыра с неотслеживаемыми файлами; с **игнорируемыми** — нет, и
намеренно: если `.gitignore` говорит, что файла в дереве нет, манифест не должен молча решать
иначе. Честный ответ — сказать, что граф построен по файлам, которые репозиторий исключает.
Диагностика `SCOPE_MEMBERSHIP` (severity `warning`), сообщение называет число и до пяти путей,
`consequence`: манифест и `scope_id` описывают не тот вход, из которого построен граф, — читать
идентичность как **unknown**.

**D3 — факт обязан ехать в графе, а не только в stderr сборки.** Диагностики печатаются при
сборке; потребитель, читающий граф и сайдкар час спустя, их не видит, а сайдкара у него может и
не быть. Поэтому сравнение выполняется на сборке (там скоуп в руках) и его **результат**
записывается в `provenance.inputs` рядом с существующими `skipped`/`aliased_modules` —
прецедент готовый: у них ровно та же роль «что экстрактор прочитал и чего не смог».

Тонкость, которую здесь нельзя проглядеть: **именно те файлы, которые ловит эта проверка, чаще
всего несут абсолютный путь** (у утёкшего узла в репорте `file` был абсолютным — симптом D5), а
блок provenance по контракту path-free и `build_provenance` на абсолютном пути **бросает
`ValueError`**. То есть наивная запись пути превратит диагностику в падение сборки. Пишем
`{"count": N, "sample": [...], "outside_root": true|false}`, где путь вне корня сводится к
базовому имени тем же правилом, что `relative_root`.

**Открытое решение (снять при реализации):** бампать ли `SCHEMA_VERSION`. Рекомендация — **нет**:
поле аддитивное и опциональное, той же формы, что `skipped`. Решается перед кодом, не после.

## 7. Приёмка

1. На синтетическом репозитории из §2: неотслеживаемый модуль **попадает** в `scope.files` с
   `tracked: false`, `scope_id` **двигается**, `--incremental` его **пересчитывает** — все четыре
   пункта сегодня проваливаются.
2. Игнорируемый модуль в `scope.files` **не попадает**, диагностика называет ровно 1 файл, и тот
   же факт виден в `provenance.inputs` у графа, прочитанного отдельно от сайдкара.
3. Регрессия на чистых деревьях: обе сборки из §5 дают 0 нарушений и 0 диагностик.
4. **Закреплённый бенчмарк R2 не двигается:** пере-материализация `bquant@cb89a24` даёт прежний
   `scope_id` `sha256:300e0a01…5e47d2`. Материализованный стейджинг — не git-дерево, то есть
   fs-режим, и D1 его не касается; но это число, на которое опираются все карточки R2, и оно
   проверяется явно, а не по рассуждению.
5. Мутационно (R1-C37): откат одной строки перечисления красит тест на неотслеживаемый модуль.

## 8. Чего мы **не** проверяли

- `watch` не запускали — вывод про него сделан по коду (`ScopeProbe` сравнивает `scope_id`).
- Глобальный `core.excludesFile` и `.git/info/exclude` — они расширяют класс «игнорируемых»
  файлов, и на них замера нет.
- Субмодули, worktrees, регистронезависимая ФС, Windows.
- Симлинк на **файл** за пределами корня (гоняли только цикл по каталогу).
- Исходный сценарий репортёра на 0.0.7 не перевоспроизводили: гварды R1-C36 приехали в 0.0.5,
  и утверждение «манифест молчал» — их замер на 0.0.4. Наша репродукция даёт то же молчание
  другим путём.
- Стоимость `--others` в цикле `watch` при коротком интервале (замерен один вызов, не цикл).
