# codemap — реестр осей обкатки (living)

**Обновлено:** 2026-08-25
**Что это.** Единый живой реестр **осей обкатки** (dogfood axes) — под каким углом мы проверяли (и
собираемся проверять) инструмент на живом коде. Заменяет оппортунистический подход «каждая обкатка
находит следующую» на **видимое покрытие**: что закрыто, что открыто, что нашли, куда дальше.

## Как этим пользоваться (принципы)

1. **Живой, не waterfall.** Все оси заранее не перечислить — обкатка по природе discovery (ось «агент
   через serve» появилась только после M3.1; F13 не был предсказан). Новые оси **дописываем строкой**
   по мере обнаружения, а не считаем список полным.
2. **Ценность спадает.** Ранние оси находили структурное (F1 область, F5 швы); поздние — эргономику
   (F9–F13). Гнать ось стоит, пока ожидаемая находка ≥ стоимости прогона. См. «критерий остановки».
3. **Одна ось за прогон.** Каждая обкатка = один угол, предрегистрированные гипотезы, прогон на живом
   графе, findings с категорией по причине (Extraction/Representation/Query-surface/Precision/Workflow/
   Soundness), затем — реализация вехой (если гэп подтверждён и стоит того).
4. **Критерий остановки оси/программы.** Останавливаемся, когда: (а) две оси подряд дали только
   мелочь/дубли, или (б) открытые оси — только «на вырост» (scale/cross-lang/RAG-eval), или (в) появился
   живой внешний потребитель → переключаемся с «улучшать» на «пользоваться/выносить в репо-продукт».

## Режим: USE-DRIVEN (с 2026-07-30) — оси добора это watchlist, не очередь

**Развилка пройдена, инструмент созрел и подключён к живому потребителю.** Сделаны все три приоритетные
оси (B1/A11/A9 → M14/M15/M16) + вынос в отдельный репо + **MCP-адаптер** (M17): codemap живёт как сторонний
тул и вызывается ИИ-агентом (Claude Code) нативно через `serve --mcp`.

**Петля «по нужде» уже сработала.** Первый прогон в бою дал **F22** (тяжёлый payload на хабах) — реальную
находку из использования, не из синтетической обкатки. Это подтвердило стоп-критерий эмпирически:
*живое использование теперь даёт находки честнее и ценнее, чем проактивный прогон осей.*

**Поэтому оси добора НЕ гоним проактивно** — держим как **watchlist с триггером**:

| Ось | Статус | Триггер «взять» |
|-----|--------|-----------------|
| A10 test-mapping | 🟡 **триггер сработал → взята 2026-08-25** | (сработал ещё 2026-07-30: реальная задача упёрлась в отсутствие среза символ→тесты) |
| A12 onboarding | ⬜ watchlist | живой запрос «проведи по подсистеме»; пересекается с discovery (A8) |
| B2 робастность | 🟡 **триггер сработал → взята 2026-08-25** | (сработал 2026-08-24: #4 namespace-dir → TypeError, #5 молчаливый пустой граф — ровно предсказанный сценарий) |
| C1/C3 | ⬜ по масштабу | больший граф / нужен embed-стенд; C2 — вне v1 |

Превращать их в запланированные вехи — gold-plating против собственного стоп-критерия. Берём **только**
когда реальное использование в них упрётся, и тогда заводим `gaps/<axis>_<date>.md` как обычно.

**Что произошло 2026-08-25 (и почему это не нарушение политики).** Триггеры A10 и B2 сработали
**сами** — A10 ещё 2026-07-30 (живая задача упёрлась), B2 — 2026-08-24, когда посторонний прогон на
втором таргете выдал ровно предсказанный этой строкой сценарий (#4/#5). Оси лежали открытыми уже
с сработавшим триггером; взяли их не проактивно, а с опозданием. Третий документ (B3/провенанс) вообще
не ось, а **эпизод**: тест детерминизма покраснел из-за сдвинувшегося входа, и различить причины было
нечем. Все три доведены до **гэп + дизайн + бэклог**; порядок постройки задан зависимостью
**R1-C25 → R1-C23 → R1-C24**, и **R1-C25 построен в тот же день** (схема 0.12) — носитель для R1-C23
D2/D6 есть.

**Что реально в работе (не ось, а нужда живого потребителя):**
- **F22** ✅ (M17-адаптер, компактный payload) — закрыто.
- **M18 freshness** 🟡 первый шаг сделан (возраст графа в `stats` + `codemap refresh` по записанному рецепту);
  полный watcher/инвалидация (M3.2) — по нужде. MCP отдаёт статичный граф → это первое трение ежедневного
  использования, ценнее любой оси добора.
- **Двух-графовый diff** (added/deleted символы для `review`) — отложено, взять при реальном PR-ревью.

*Полевые находки из использования пишем в `BACKLOG.md` (раздел «находки из живого MCP-использования»),
не в отдельный dogfood-док — обкатки-по-осям завершены.*
