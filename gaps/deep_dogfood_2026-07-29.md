## 1. Зачем ещё одна обкатка

Две прошлые обкатки были **одноосевые** и каждая нашла ровно один доминирующий гэп
(F1 — область → M6; F5 — швы диспетчеризации → M7). Обе оси теперь закрыты. Чтобы найти
**больше реальных нестыковок**, эта обкатка сознательно **перебирает архетипы вопросов**,
которые инструмент ещё не нагружал, — по одной реальной задаче bquant на каждый, с
предрегистрацией «где сломается».

### Покрытые оси (нагружали)
- **reverse-impact** — «кто использует X» → F1 (закрыт M6).
- **forward-callchain** — «что исполняется при X» → F5 (закрыт M7).

### Непокрытые оси (нагружаем здесь)
- **contract/exemplar** — «как расширить точку расширения» (T1).
- **dataflow по строковому ключу** — «проследи колонку датафрейма» (T2).
- **change-set reasoning** — «что сломает смена сигнатуры» (T3).
- **RAG-самодостаточность** — «дай чанк, достаточный для правки» (T4).
- **reachability/dead-code после M7** — регресс-проверка достижимости (T5).

## 2. Таксономия гэпов (классифицируем по причине, не симптому)

| Категория | Значение | Прецедент |
|---|---|---|
| **Extraction** | инфы нет в графе вообще | F1 |
| **Representation** | инфа есть, но не в той форме под вопрос | F3 |
| **Query-surface** | инфа есть, но спросить нечем | F2 |
| **Precision** | есть, но over/under-approximation | F5-мост |

Каждая находка ниже получает категорию — это прямо диктует форму фикса (новый экстрактор /
новый вид / новая команда / уточнение метки).

## 3. Конфигурация прогона

- **Граф:** repo-scoped, `--mode full --deep` (честная полная конфигурация: ядро + потребители
  tests/examples/research/scripts + доки). Тот же билд, что в обкатке-2 / M7.
- **Правило:** каждую задачу решаем **только через codemap** (указываем команду/вид). Где
  приходится звать grep/чтение — это и есть гэп.
- **Вывод на задачу:** вопрос потребителя → попытка (команда) → вердикт **полно / частично /
  никак** → ground-truth (grep/чтение) → категория гэпа → id находки `F6…` или «покрыто».
- Спайк-скрипты — в scratchpad, в репо не тащим. `bquest` не трогаем.

## 4. Пять задач и предрегистрированные гипотезы

### T1 — Extension: «добавь новую swing-стратегию, как ZigZag»
**Потребитель:** ИИ/разработчик реализует фичу на точке расширения.
**Что нужно из графа:** (i) контракт (методы Protocol + сигнатуры), (ii) шов регистрации,
(iii) путь конструирования/проводки, (iv) образец-реализация.
**Виды:** `query SwingStrategy`, `export rag` на существующей стратегии, `export mermaid --mkind class`.
**Гипотеза H1:** члены реестра (данные M7) в графе есть, но **нет вида «семейство/контракт»** —
из графа не собирается «эти N классов = семейство swing, обязаны реализовать `calculate_*`;
вот образец». → ожидаю подтверждение **F4** + возможный новый *representation/query-surface* гэп.

### T2 — Dataflow по строковому ключу: «проследи колонку `macd_hist` от производства до потребления»
**Потребитель:** отладка «почему метрика зоны кривая».
**Что нужно:** пройти по датафрейм-колонке (`indicator_col='macd_hist'`), не по символу.
**Виды:** — (кандидатов почти нет; попробуем `query`, `rag` текст-поиск).
**Гипотеза H2:** **extraction-гэп** — строковые колонки датафрейма невидимы графу; связь
«кто пишет `df['macd_hist']` ↔ кто читает» не выражается. Сильный кандидат в **F6 (dataflow-blindness
по строковым ключам)**.

### T3 — Change-set: «поменяй сигнатуру ходового core-fn (напр. `get_indicator_params`)»
**Потребитель:** рефактор с breaking-change.
**Что нужно:** не просто «кто ссылается», а «какие call-sites реально **сломаются**»
(позиционные аргументы / kwargs / арность).
**Виды:** `report impact --symbol`, `query`.
**Гипотеза H3:** `impact` — на уровне **ссылок**, а не арности/аргументов вызова; для рефактора
он даёт список-кандидат, но не отличает ломкий call-site от безобидного упоминания. →
*precision/representation* гэп, кандидат **F7 (call-site без арг-контракта)**.

### T4 — RAG-самодостаточность: «дай достаточно, чтобы модифицировать `MACDZoneAnalyzer`»
**Потребитель:** ИИ-редактор, собирающий контекст под правку.
**Что нужно:** самодостаточный чанк — что класс делает, что вызывает, куда делегирует
(deprecated → делегирует в pipeline), кто его зовёт.
**Виды:** `export rag` (чанк класса).
**Гипотеза H4:** **F3 подтверждён** — класс-чанк не агрегирует call-соседей своих методов;
шов делегирования (метод → `analyze_zones`) виден на ребре метода, но не в чанке класса. →
*representation* гэп.

### T5 — Reachability/dead-code после M7 (регресс)
**Потребитель:** аудит «что мёртвое / все ли точки входа достижимы».
**Что нужно:** `report dead-code`, сверка с реальностью.
**Виды:** `report dead-code`.
**Гипотеза H5:** взаимодействие мост-рёбер M7 с dead-code не проверено. Либо (a) registry-
impl'ы теперь корректно достижимы через мост (регресс OK), либо (b) dead-code даёт
false-positive на плагинах (зарегистрированы, но зовутся только динамически) / наоборот
false-negative. Кандидат **F8**.
