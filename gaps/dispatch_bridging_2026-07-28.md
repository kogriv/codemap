## 1. Задача обкатки

После M6 (область закрыта) взяли задачу на **другой оси** — не «кто использует X», а
«**проследить, что исполняется при `analyze_zones`, по цепочке вызовов**» (навигация ИИ,
потребитель A). Трассировали BFS по `calls`-рёбрам deep-графа от `analyze_zones` и сверили
с исходником.

## 2. Что нашли — F5: слепота на швах диспетчеризации

Цепочка дошла до **38 узлов, глубина 3**, и оборвалась ровно на **двух плагин-швах**:

| Шов | Как устроено (bquant) | Что видел граф |
|-----|------------------------|-----------------|
| детекция зон | `ZoneDetectionRegistry.get(name)` → детектор через переменную | обрыв: какой детектор — неизвестно |
| стратегии фич | `self.swing_strategy = create_swing_strategy(name)` в `__init__`, затем `self.swing_strategy.calculate_global(...)` | `extract_zone_features`: **86/147 вызовов unresolved** |

То есть **самое смысловое — какая стратегия/детектор реально исполняется — ровно то, что в
тени.** Здесь сходятся потолок локалей (M5, ~25.7%) и динамическая проводка (§7). ИИ,
навигируя по цепочке, упирается в стену на точке расширения — там, где важнее всего.

**Отличие от F1.** F1 — про **область** (не видели потребителей, закрыт M6). F5 — про
**глубину на швах**: видим оркестрацию, но не «что исполняется в точке диспетчеризации».

## 3. Ключ: данные для моста уже есть

M1.5 записал **таблицу диспетчеризации** — каждый `@Registry.register('key')` в
`extras.registry` ({key → class}); на bquant это 12 привязок (`zero_crossing`→ZeroCrossingDetection,
`find_peaks`→FindPeaksSwingStrategy, …). Protocol-базы — узлы. Конкретные стратегии Protocol
**не наследуют** (структурная типизация) → группировать по наследованию нельзя, только по
**регистратору**. Не хватало лишь ребра от call-site к таблице.

## 4. Тэйк (решение) — M7: registry-aware call bridging

**Мост через реестр, best-effort, честно помеченный.** `extract/dispatch.py`, отдельный проход
после поведенческого, читает таблицу M1.5:

- **Семейства** группируются по регистратору: `StrategyRegistry.register_swing_strategy` →
  (StrategyRegistry, «swing»); `ZoneDetectionRegistry.register` → по классу реестра.
- **Атрибут класса ↔ семейство:** `self.attr = create_X(...)` в любом методе класса → `attr`
  привязан к семейству X.
- **Мост метода:** `self.attr.method(...)` → рёбра к `{impl}.method` всех реализаций семейства,
  метка `resolution="registry-candidate"` (over-approximation: «одна из семейства»).
- **Прямой вызов фабрики/геттера** → рёбра к классам-реализациям; при **строковом литерале**
  ключа — единственное точное ребро `resolution="registry"`.

Рёбра — тип `calls`, поэтому цепочка/impact/callers/RAG **сразу** их подхватывают.

### Честность

- **Candidate ≠ точное.** Линкует во ВСЕ реализации семейства — реально исполняется одна.
  Для навигации «диспетчеризует в один из {zigzag, find_peaks, …}» несравнимо лучше молчания;
  для точного счёта — нет. Метка на каждом ребре; `report behavior` считает мосты отдельно.
- **Счётчик покрытия не трогаем.** Per-function `extras.calls` (exact-резолв) остаётся как был
  (28.2% unresolved) — мост это отдельный overlay, а не подкрутка честной метрики.

## 5. Результат (замер на bquant)

| | до M7 | после M7 |
|---|-------|----------|
| цепочка от `analyze_zones` | 38 узлов, глубина 3 | **116 узлов, глубина 7** |
| швы | 2 оборваны | реконнекчены |
| мост-рёбра | — | **44** (0 exact / 44 candidate; флагман — нелитеральные ключи) |

`_detect_zones` → все 5 детекторов; `extract_zone_features` → `FindPeaksSwingStrategy.calculate`,
`ClassicDivergenceStrategy.calculate_divergence` и т.д. — **цепочка дошла до реальных compute-методов.**
Мост тир-независим (работает и на fast). Сборка deep ~53с. 63/63 теста; детерминизм.

## 6. Граница

- **Точную ветку** (какой именно ключ пришёл из config/параметра) статически не берём — это тот
  же неразрешимый рантайм. Отдаём семейство-кандидатов, не одиночку. Литеральный ключ — исключение
  (берём точно).
- Мост опирается на **соглашение об именовании** регистратора/фабрики (`register_swing_strategy`
  ↔ `create_swing_strategy`, токен семейства). Токены берутся из таблицы реестра (data-driven),
  не хардкод; но чужой проект с другим соглашением потребует настройки распознавателя.
