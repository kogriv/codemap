# Гэп: вне Python каталог не может дать совета, только список

**Дата:** 2026-11-21. **Источник:** вопрос владельца «если придёт проект на Rust, что codemap ему посоветует?»
сразу после выпуска `advise` (0.0.40). **Статус:** открыт; дизайн — [`docs/design/recipe_rust.md`](../docs/design/recipe_rust.md),
бэклог R1-C111.

## 1. Что показал вопрос

- Для графа вызовов Rust `advise` выдавал 14 инструментов, все «прочтён». Список честный, но выбрать по нему
  нельзя.
- Два дефекта сразу исправлены в 0.0.41. Фильтр по языку пропускал инструменты для других языков (radon для
  Rust). Замер на Python читался как «измерен» для любого языка.
- Штатных средств экосистемы Rust в каталоге не было совсем: rust-analyzer, clippy, cargo-audit, cargo-deny,
  cargo-machete, cargo-modules.
- Ни один из разобранных лабораторией инструментов (GitNexus, CodeGraph, OntoIndex, roam-code, graphlens) не
  запускался на коде не на Python, хотя все заявляют Rust.

## 2. Чего не хватает

**(a) Рецепта.** Агенту в Rust-проекте нужен ответ «что ставить для такой-то задачи, в каком порядке и почему»,
а не перечень.

**(b) Эталона вне Python.** Вся правда лаборатории — граф bquant. Сверять ответы инструментов на Rust не с чем.

**(c) Замеров разобранных инструментов на другом языке.** Самое ценное знание — насколько верны агентские графы
(MCP) на Rust по сравнению с компиляторным эталоном. Его нет ни у кого, включая нас.

## 3. Чем это опасно

Агент в Rust-проекте либо берёт первый попавшийся инструмент, либо верит заявлению из README. Устроенный на
tree-sitter граф без разрешения типов на трейтах и макросах может уверенно ошибаться. На Python лаборатория это
видела у grafema: подмена одноимённого метода без флага.

## 4. Что закрывает гэп

R1-C111: рецепт для Rust в каталоге; эталон на rust-analyzer по публичному репозиторию с закреплённым коммитом;
замеры разобранных инструментов на нём с `measured_on = ["rust"]`. Подробности и ожидания — в дизайне.
