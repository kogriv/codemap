# Гэп: граф, собранный в другом каталоге, печатает `pytest`-строку, которую CLI не умеет поправить

**Дата:** 2026-11-05. **Источник:** bquant (bquant#120, заказ 2): граф собирается post-commit на другой машине
и копируется в рабочий каталог. Сводка — [kogriv/codemap#25](https://github.com/kogriv/codemap/issues/25).
**Статус:** ✅ закрыто 2026-11-05 (0.0.29); дизайн — [`docs/design/foreign_graph_paths.md`](../docs/design/foreign_graph_paths.md),
бэклог R1-C83.

## 1. Что показали

Фикстура `pkg/` + `tests/`, `main` a305b1d. Граф собран, затем в сайдкаре `roots_base` заменён на каталог,
которого здесь нет. Так выглядит граф, собранный на другой машине:

```
из корня репозитория:  pytest tests/test_a.py::test_a                         ← строка верна
                       · 1 of 1 path(s) could not be located on this machine … relative to `/srv/elsewhere/c84`
из родителя:           pytest tests/test_a.py::test_a                         ← строка неверна
                       · то же предупреждение; поправить нечем: у `tests` нет флага корня
без сайдкара:          · paths are relative to the build roots' common directory — run from there …
                       (тоже из корня, где путь существует)
```

У `serve` есть `--source-root`. У CLI `tests` его нет. В `report dead-code` код читает
`getattr(args, "source_root")`, но флага в парсере нет, поэтому `codemap.toml` с белым списком всегда
читается из текущего каталога.

Заявление из отчёта «`query` тоже пишет could not be located» не подтвердилось. CLI `query` не переписывает
пути: он печатает их как граф их хранит, и сообщения этого нет нигде, кроме `tests`.

## 2. Почему так

`_local_nodeids` (R1-C31) переписывает путь только относительно `roots_base` из сайдкара. Это верно для графа,
собранного здесь. Если каталога из сайдкара на этой машине нет, второго кандидата не пробуют, даже когда файл
лежит прямо в текущем каталоге. Явно указать корень тоже нельзя.

## 3. Чем это опасно

- **Ложная тревога.** Строка верна, а предупреждение говорит, что пути не найдены. Предупреждение, которое
  кричит на верный ответ, учит его не читать, и в тот день, когда оно будет право, его пропустят.
- **Неисправимый ответ.** Из любого другого каталога строка неверна, а способа сказать «корень вот здесь» нет.
  Сосед, у которого граф собирается вне рабочей копии (а это теперь штатная схема: post-commit на другой машине),
  получает этот случай всегда.
