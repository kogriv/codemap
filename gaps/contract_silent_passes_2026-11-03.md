# Тихие проходы гейта контракта — проба `codemap check` по следам grafema (2026-11-03)

**Откуда.** Второй проход карточки grafema ([`research/tools/grafema.md`](../research/tools/grafema.md) §6.6)
нашёл у чужого гейта контракта три тихих прохода:
- первый `check` на свежем графе ничего не проверяет и выходит с exit 0;
- правило с опечаткой в предикате проходит без предупреждения, хотя документация его обещает;
- правленое правило продолжает работать в старом виде.

Владелец решил проверить, что делает `codemap check` в тех же ситуациях. Это **проба**, а не
утверждение, что codemap уже справляется.

**Что известно до прогона, из чтения кода** (`codemap/arch.py`, `codemap/cli.py`, `codemap/serve/session.py`):
- нечитаемый `codemap.toml` даёт exit 2 (R1-C27);
- пустой или отсутствующий контракт даёт exit 0 с путём к файлу, а `--require-contract` делает его ошибкой
  (R1-C35);
- имена, которых нет в графе, показываются как «declared vs applicable» (R1-C62). Отказ при этом
  включается только флагом `no_phantom_rules`;
- `parse_contract` читает известные ключи через `section.get(...)`. Неизвестные ключи и элементы
  неверной формы, по коду, отбрасываются без следа;
- булевы поля берутся через `bool(...)`, списки — через `tuple(...)`;
- MCP-операция `check` читает `codemap.toml` при каждом вызове.

## Предрегистрация (коммит до прогона)

**Фикстура:** пакет `pkg` со слоями `core` и `analysis`, где `pkg/core/a.py` делает `import pkg.analysis.b`.
`codemap check --build <фикстура>/pkg --root <каталог с codemap.toml>`, свежий каталог на каждый случай.
Сборка фикстуры занимает секунды и идёт локально.

| | `[architecture]` | ожидание | если так, это |
|---|---|---|---|
| **K0** контроль | `forbidden = [{from="core", to="analysis"}]` | exit 2, ребро `core.a → analysis.b` названо | — |
| **P1** опечатка в ключе, единственное правило | `forbiden = [{from="core", to="analysis"}]` | exit 0, вывод «контракта нет», ключ `forbiden` не упомянут | **дефект**: аналог `edgee` у grafema |
| **P1b** опечатка рядом с верным правилом | `no_cycles = true` + `forbiden = [...]` | exit 0, проверены только циклы, `forbiden` не упомянут | **дефект** |
| **P2** элемент неверной формы | `forbidden = [{from="core", too="analysis"}]` | exit 0, «контракта нет», элемент не упомянут | **дефект** |
| **P2b** группа из одного | `independent = [["core"]]` | exit 0, «контракта нет» | **дефект** (мелкий) |
| **P2c** строка вместо булева | `no_cycles = "false"` | правило **включено**, потому что `bool("false")` даёт True | **дефект**: значение читается наоборот |
| **P2d** строка вместо списка | `layers = "core"` | четыре однобуквенных слоя `c`, `o`, `r`, `e`, показанных как несуществующие; exit 0 | **дефект**, хотя он и виден в выводе |
| **P3** несуществующее имя | `forbidden = [{from="core", to="analysys"}]` | exit 0, `analysys` назван как отсутствующий, «1 declared, 0 applicable» | держится (R1-C62) |
| **P4** контракта нет | без `[architecture]` | exit 0 с путём; с `--require-contract` — ненулевой код | держится |
| **P5** правка между вызовами MCP | `check` на сессии `serve`, правка `codemap.toml`, снова `check` без `reload` | второй ответ отражает правку | держится: аналог G5 у grafema не воспроизводится |
| **P6** граф старше исходника | `codemap build` → граф; затем в исходник добавлен нарушающий импорт; `check --graph <старый граф>` | exit 0, нарушение не найдено, о возрасте графа ни слова | **дефект?** У grafema есть «Graph is fresh» перед `check` |

Хотя бы одно ожидание должно провалиться, если в коде ничего не устроено так, как я прочёл. Это K0
(контроль) и P3–P5 (то, что я считаю уже сделанным).

**Что проба не устанавливает:** поведение `[integrations]` и whitelist-загрузчика (там тот же
`read_toml`, но другие парсеры); Python, кроме 3.12.

**Если дефекты подтвердятся,** починка идёт отдельной вехой (R1-C, design → код → приёмка → мутация
стража → доки), а не в этом коммите.

## Сверка (2026-11-03)

codemap из рабочего дерева (0.0.22 + docs), Python 3.12, фикстура собрана локально, каждый случай в
своём каталоге.

**Контроль K0 сначала не прошёл,** и это главная находка пробы, хотя предрегистрация её не
предвидела. Фикстура импортировала через `import pkg.analysis.b`, и гейт ответил «✅ Contract
satisfied». Причина в графе: эта форма даёт ребро `pkg.core.a → pkg`, в корень пакета, поэтому слоя
`analysis` в ребре нет. Разбор по формам, по одной на фикстуру:

| форма в `pkg/core/a.py` | ребро `imports` |
|---|---|
| `import pkg.analysis.b` | `pkg.core.a → pkg` ✗ |
| `import pkg.analysis` | `pkg.core.a → pkg` ✗ |
| `import pkg.analysis.b as bb` | `→ pkg.analysis.b` ✓ |
| `from pkg.analysis import b` | `→ pkg.analysis.b` ✓ |
| `from pkg.analysis.b import X` | `→ pkg.analysis.b` ✓ |
| `from ..analysis import b` | `→ pkg.analysis.b` ✓ |
| `from ..analysis.b import X` | `→ pkg.analysis.b` ✓ |

То же самое в `--deep`. Механизм: griffe хранит импорт как «связанное имя → путь». Для `import a.b.c`
связанное имя `a`, и путь записан как `a`. Python при этом загружает `a`, `a.b` и `a.b.c`, так что
зависимость от `a.b.c` настоящая. Ни в bquant, ни в самом codemap эта форма не встречается ни разу
(`git grep` по `^\s*import <pkg>\.`). Поэтому эталон R2 из 266 рёбер её и не ловил. **Гейт слеп к
этой форме записи. Это тот же класс, что G3 у grafema: контракт наследует слепоту резолвера.**

После замены импорта на `from pkg.analysis import b` контроль прошёл: exit 2, ребро
`pkg.core.a → pkg.analysis.b` названо. Ниже — результаты на этой фикстуре.

| | ожидание | замер | |
|---|---|---|---|
| K0 | exit 2, ребро названо | exit 2, `pkg.core.a → pkg.analysis.b` | держится (на второй форме) |
| P1 `forbiden` | exit 0, «контракта нет», ключ не упомянут | exit 0, «No `[architecture]` contract found … nothing to enforce» | **дефект подтверждён**, и причина в выводе названа неверно: секция есть |
| P1b `forbiden` + `no_cycles` | exit 0, только циклы, ключ не упомянут | «Rules enforced: no_cycles», exit 0 | **дефект подтверждён** |
| P2 `too=` | exit 0, «контракта нет» | так и есть | **дефект подтверждён** |
| P2b группа из одного | exit 0, «контракта нет» | так и есть | **дефект подтверждён** |
| P2c `no_cycles = "false"` | правило включено | «Rules enforced: no_cycles» | **дефект подтверждён** |
| P2d `layers = "core"` | слои `c`, `o`, `r`, `e`, exit 0 | «layered (4 declared, 0 applicable)», названы `c`, `e`, `o`, `r` | **дефект подтверждён**, виден в выводе |
| P3 `analysys` | exit 0, имя названо отсутствующим | «forbidden (1 declared, 0 applicable)», `analysys` назван | держится |
| P4 контракта нет | exit 0 с путём; `--require-contract` ≠ 0 | exit 0 с путём; exit 1 с `--require-contract` | держится |
| P5 правка между вызовами MCP | второй ответ видит правку | 1 нарушение → правка → 0, `ok: true` | держится |
| P6 граф старше исходника | exit 0, о возрасте ни слова | «✅ Contract satisfied», exit 0. Контроль `--build` на том же дереве: exit 2 | **дефект подтверждён** |

**Итого — три класса, все про то, что гейт говорит «ок», не проверив:**
1. **Форма `import a.b.c`** теряет цель ребра. Это бьёт не только по гейту, но и по `impact`,
   `architecture` и циклам. Самое серьёзное из найденного.
2. **Схема `[architecture]` не валидируется.** Неизвестный ключ, элемент неверной формы, строка
   вместо булева или списка проходят молча или читаются наоборот. Аналог `edgee` у grafema, только
   у нас без обещания предупреждения: не обещано и не сделано.
3. **`check --graph` не сверяет граф с деревом.** Нужные для этого данные уже есть: `scope_id` в
   сайдкаре, R1-C25/R1-C31.

**Сюрприз:** класс 1 не предвиделся. Его нашёл провал собственного контроля, а не предсказание.

**R1-C68 закрыт 2026-11-03** (дизайн [`docs/design/dotted_imports.md`](../docs/design/dotted_imports.md), приёмка там же): `import a.b.c` даёт ребро в `a.b.c`, гейт на фикстуре K0 с этой формой теперь даёт exit 2.

**R1-C69 закрыт 2026-11-03** ([`docs/design/contract_validation.md`](../docs/design/contract_validation.md)): контракт с любой ошибкой схемы отклоняется целиком, exit 2, все проблемы названы.

**Дальше:** три кандидата в BACKLOG как R1-C. Починка — отдельными вехами (design → код → приёмка
→ мутация стража → доки). Решение о порядке за владельцем; рекомендация — класс 1 первым.
