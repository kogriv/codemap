# Гэп: пустой ответ не говорит, какого он рода — «ссылок нет» и «символа нет» неразличимы

**Дата:** 2026-09-03. **Источник:** собственная ошибка по ходу замера под дверь (3) R1-C43 —
зонд искал `bquant.…` на графе, который корнится именем каталога и потому нёс id `target.…`.
Два прогона, восемнадцать глубоких сборок, около двадцати минут счёта не измерили **ничего**, и
это выглядело как результат: «ребра нет» — правдоподобный исход с ожидаемой частотой 25 %.
**Статус:** измерено; починка не сделана, решения — [`docs/design/absent_answers.md`](../docs/design/absent_answers.md).

Всё ниже снято на `codemap 0.0.10 @2edf09d` (чистый чекаут), jedi 0.20.0, parso 0.8.7, на дереве
`bquant@cf7c6e1` (88 модулей), запиненном `git archive` и сверенном побайтно с локальной копией
(88 файлов, одинаковый хеш-набор; первое расхождение оказалось локалью сортировки `find | sort`,
а не содержимым).

## 1. Что отвечает инструмент о символе, которого в графе нет

```
impact("bquant.nosuch.module.Ghost.field")
  -> {"ok": true, "result": {"symbol": "bquant.nosuch.module.Ghost.field",
                             "impact": [], "markdown": "# Impact — …"}}
callers(…)  -> {"ok": true, "result": [], "epistemic": {"epistemic": "partial", …}}
callees(…)  -> {"ok": true, "result": [], "epistemic": {"epistemic": "partial", …}}
flows(…)    -> {"ok": true, "result": {"entry": "bquant.nosuch…", "edges": [],
                                       "reached": 0, "max_depth": 0}}
```

На уровне `Query` тот же ответ несёт **утвердительный вердикт**:

```
Query.impact(ghost) -> {"refs": [], "by_root": {}, "by_distance": {},
                        "max_distance": 0, "risk": "none"}
```

`risk: "none"` — «ничто от этого не зависит» — про символ, о котором инструмент никогда не слышал.

**Ответы про призрак и про настоящий символ без ссылок совпадают побайтно.** Проверено на реальном
графе `bquant` (4840 узлов): `callers` на призрак и `callers` на существующий атрибут возвращают
одинаковый конверт целиком, включая `epistemic`.

## 2. Инструмент это знает — и выбрасывает

```python
Query.canonical(ghost)       -> None
Query.canonical_info(ghost)  -> None
```

Резолвер отвечает правильно. Теряется ответ на один переход дальше, в `serve/session.py`:

```python
def _canon(self, name_or_id):
    info = self.query.canonical_info(name_or_id)
    self._resolution = info          # None, когда символа нет
    return info["id"] if info else name_or_id   # ← и дальше едет сырой ввод

# handle():
r = self._resolution
if r and (r["ambiguous"] or r["input"] != r["id"]):
    env["resolved"] = r
```

`if r` — ложность самого `r` съедает **тот единственный случай, ради которого блок `resolved` и
заведён**. Блок сообщает «имя разрешилось неоднозначно» и «имя переписано в канонический id»; он
не сообщает «имя не разрешилось вовсе», потому что это состояние представлено `None`, а `None`
фильтруется как «нечего сообщать».

Плюс `return … else name_or_id`: неразрешённый ввод едет дальше как будто это id, и все нижние
слои честно ищут его в графе, ничего не находят и рапортуют пустоту.

## 3. Почему это тяжелее двери (3), из-за которой нашлось

| | дверь (3) R1-C43 | этот гэп |
|---|---|---|
| условие | `tier: deep` **и** `incremental: true` | **никакого** — любой граф, включая полную сборку |
| источник пустоты | ребро потеряно шумом и заморожено сплайсом | символа нет вовсе |
| замерено последствий для вердиктов | **0** (см. §4) | вердикт `risk: "none"` выдаётся всегда |
| стоимость починки | новая категория раскрытия, правки в N поверхностях | резолюция уже вычислена, её надо не выбрасывать |

## 4. Заодно замерено: шум тира вердикт **не** переворачивает

Шесть полных deep-сборок замороженного дерева (то же дерево, тот же инструмент):

| | |
|---|---|
| рёбер по сборкам | 9157, 9157, 9158, 9158, 9158, 9158 |
| символов с гуляющим счётчиком ссылок | **1** из 2869 узлов |
| из них достигают **нуля** хотя бы в одной сборке | **0** |
| кандидаты dead-code | объединение 3, в каждой сборке 3, гуляющих **0** |
| тот же кандидат с другой уверенностью | **0** |

И то же самое на тройке «истина / шум / заморожено» (граф с ребром, граф без него, и он же после
инкрементальной пересборки, `affected = 3`):

| | истина | шум | заморожен |
|---|---|---|---|
| `provenance.incremental` | false | false | **true** |
| диагностики | `deep_tier_unstable` | `deep_tier_unstable` | + **`incremental_deep_splice`** |
| `references_to(swing_strategy)` | **4** | 3 | 3 |
| `impact` | refs **7**, risk `medium` | refs 4, risk `medium` | refs 4, risk `medium` |
| `dead_code` | 3 кандидата, 2 high | 3 / 2 high | 3 / 2 high |

**Раскрытие работает** — нота на замороженном графе есть, на полных нет. **Дальше неё не
происходит ничего:** `impact` отдаёт `refs=4, risk=medium` тем же тоном, что `refs=7` на истине,
то есть 43 % ссылок пропало без признака в самом ответе, а `references_to` не входит даже в
`_PARTIAL_OPS` и не получает общего `epistemic`.

**Но ни один вердикт не перевернулся.** Двигались счётчики, не выводы. Это ослабляет исходную
формулировку двери (3) («всё, что заключает об отсутствии, отвечает `unknown`») и требует её
сузить — см. дизайн, D2.

## 5. Три сопутствующие находки

1. **`cli.py:885`, текст `--help` у `--incremental`:** «Reuse an existing --out graph… **Identical
   to a full build**; much faster on `--deep`». Без тира — ровно то утверждение, которое R1-C43
   опроверг для deep. **Пятая копия**, и самая видимая: её читают, решая, включать ли флаг.
   Вчерашняя правка дошла до `docs/incremental.md`, docstring модуля и docstring теста — и не
   дошла сюда. Прогреп по всему дереву: остальные живые копии тир-квалифицированы
   (`README.md:261` — «byte-identical on the fast tier»), в `CHANGELOG.md` остаются исторические
   записи, их не переписываем.
2. **`--incremental` вместе с `--consumer/--docs` молча проглатывается:** ветка
   `if args.consumer or args.docs:` в `cli.py:86` выигрывает, пользователь получает полную
   репо-сборку. Ответ верный, флаг съеден без слова. Граница дизайна (инкремент однопакетный)
   существует, но не проговаривается.
3. **Граф корнится именем каталога.** Мишень, скопированная под другим именем, отвечает молчанием
   на все id-вопросы, и это молчание неотличимо от честного «ссылок нет» — §1 в чистом виде.
   Поведение само по себе правильное; неправильно, что о нём нельзя узнать из ответа.

## 6. Урок метода

У нас записано: **проверка, которой ни разу не показывали то, что она обязана отвергнуть, — не
проверка** (R1-C37). У правила не хватало симметричной половины, и она стоила сегодня двадцати
минут счёта:

> **Зонд, которому ни разу не показывали то, что он обязан найти, — не зонд.**

Одна сборка с печатью нескольких id узлов стоила бы 70 секунд и закрыла бы вопрос. Вместо этого
восемь отрицательных ответов подряд были прочитаны как измерение, и причина искалась в дереве и в
окружении — то есть везде, кроме собственного вопроса.

## 7. Чего мы **не** проверяли

- Не искали символ, у которого **единственная** ссылка — гуляющая: на этом дереве таких не нашлось
  (§4), на другом дереве вердикт мог бы перевернуться. Утверждения «не может» у нас нет.
- Не мерили, как ведут себя остальные поверхности (`check`, `diff`, `review`, `architecture`,
  `pack`) на призрачном вводе — §1 снят на четырёх операциях из примерно двадцати.
- Не проверяли, есть ли тот же класс у **файловых** вводов (`symbol_at`, `columns_of`) и у
  `column`/`covers`, где ключ не символ.
- Не мерили частоту в реальном использовании: сколько запросов к MCP приходит с опечаткой в id.
  Без этого «сколько раз это уже соврало» — неизвестно, а не ноль.
