# Дизайн — вызовы через типизированное поле и учёт codemap CLI

**Статус:** реализовано и проверено 2026-11-24. **Бэклог:** R1-C147, R1-C148.
**Гэп:** [F1–F2](../../gaps/fast_fields_and_devkit_cli_usage_2026-11-24.md).

## D1 — Перенос простой аннотации параметра в поле

На fast распознать в обычном `__init__` прямое присваивание
`self.field = parameter` в теле конструктора. Аннотированный параметр
должен именовать конкретный класс из этого модуля, включая отложенную
аннотацию и строковую запись. Для bare-аннотации без future import
использовать класс, определённый выше. Тип поля не переносится в подкласс
обёртки. Для вызова `self.field.method()` из другого метода требуется
определение метода на названном классе в графе.

При нескольких видимых записях или удалении этого поля, затенённом параметре,
неоднозначном конструкторе и сложной аннотации маршрут остаётся неразрешённым.
Ребро маркируется `resolution: annotated-field`, грейд `inferred`. Из
аннотации следует статический тип, а Python допускает другое значение,
подкласс или динамическую запись за пределами класса. Не понижать целый
класс кандидатов в dead code из-за любого неразрешённого вызова.

Переиспользовать существующие подсчёт вызовов и учёт формы аргументов.
Deep сохраняет свой маршрут и использует fast как обычный fallback.
Схема графа прежняя, новый маршрут описывается в словаре `RESOLUTIONS`.

## D2 — Раздельный учёт MCP, CLI и grep

Считать одну запись на уникальный идентификатор tool-use в каждой применимой
категории. MCP-счётчики `codemap` и `codemap_total` сохраняют смысл.
Добавить `codemap_cli` для распознанных CLI tool-use и `codemap_cli_total`.
В тексте и JSON назвать долю: (MCP + CLI) / (MCP + CLI + grep).
Смешанный Bash-вызов попадает по одному разу в CLI и grep. Отчёт выводит
счётчики, а не исходные Bash-команды и текст сообщений.

Сканировать простые позиции команд, включая составные строки Bash и вызовы
через путь, `python -m codemap` или `uv run`. Цитата с примером и аргумент
другой команды не считаются запуском codemap. Это статический подсчёт
запросов к инструментам, он не подтверждает исполнение каждой ветки,
развёртывание shell-функций, heredoc и удалённые команды.

## Предварительная приёмка

| # | Проверка | Контроль |

| E4 | Пайплайн с CLI и grep учитывается в обеих категориях, а два CLI в одном Bash tool-use учитываются один раз. | JSON и Markdown сообщают одинаковые числитель, знаменатель и состав доли. |

## Сверка 2026-11-24

E1–E4 прошли на [синтетических регрессиях](../../tests/test_fast_field_and_usage.py).
На `v0.0.47` та же фикстура fast показала пустой `callers` и `Worker._work`
в `dead-code high`. Для CLI без MCP первоначальный тест воспроизвёл
отсутствие счётчика CLI. Закрытый словарь маршрутов включает `annotated-field`,
а закреплённый Markdown-отчёт обновлён для пояснения грейда `inferred`.

Полный `pytest` на `m99`, Python 3.12.16, `bquant` на коммите
`274ab46c4b3e9fb17f56057dcec56a6154493d37`: 1520 прошли, 3 пропущены из-за
отсутствия `ccc`, `readtags` и `scip`. На HP выполнены целевые проверки и сбор
списка тестов. Остальные версии Python входят в матрицу CI для pull request.

## Проверка опубликованной версии на потребительском проекте

Автор исходного отчёта установил `codmap 0.0.48` с PyPI в изолированное окружение
и повторил статические проверки. Fast-граф показал входящий вызов через поле,
и живой метод исчез из `dead-code high`. На одном и том же окне журналов
Claude Code отчёт `devkit usage` показал ненулевой счётчик CLI и ненулевую долю
при прежних значениях MCP и grep. Строгая проверка архитектурного контракта
прошла на свежем графе. Проверка потребительского проекта была статической.
