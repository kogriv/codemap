# Design — правило контракта, которому нечего покрывать, считалось выполненным

**Статус:** ✅ **сделано** (2026-09-26, без изменения схемы; сьют 972 → 983). **Мотивирует:** R1-C62, интейк
[`../../research/05_curated_sources.md`](../../research/05_curated_sources.md) §4a — чужой репозиторий про
устаревающие требования, прогнанный у нас. **Бэклог:** R1-C62. **Пользовательские доки:**
[`../architecture-contracts.md`](../architecture-contracts.md).

**Неизменные инварианты:** source-only, детерминизм, два тира, resolved-or-honestly-flagged, закрытый
словарь рёбер, `extras` открытый, ответ называет, чего он не судил.

---

## 1. Что показал замер

Фикстура: пакет из двух слоёв, `api` и `core`. Контракт, в котором **все** имена вымышлены:

```toml
[architecture]
layers = ["frontend", "middleware", "persistence"]
independent = [["frontend", "middleware"]]
forbidden = [{ from = "middleware", to = "persistence" }]
no_cycles = true
```

```
✅ Contract satisfied. Rules enforced: layered (3), independent (1), forbidden (1), no_cycles.
exit 0
```

Шесть правил объявлены выполненными; сработать не может ни одно, кроме `no_cycles`.

**И вот главное, что нужно сказать прямо: инертность таких правил — не недосмотр, а решение, принятое
раньше и записанное.** Докстринг `codemap/arch.py` с самого начала гласит:

> Rules that reference a layer not present in the graph are simply inert (no module → no edge to break),
> so a contract can be written ahead of the code.

Это полезное свойство, и ломать его нельзя: контракт пишут заранее, слой бывает запланирован и пуст,
`forbidden` держат как страховку на будущее. **Дефект не в семантике, а в отчёте:** строка
«Rules enforced: layered (3)» — утверждение о факте, и оно неверно; три правила не enforced, они
не применимы. А «✅» рядом читается как «покрыто».

Это семья R1-C28 (**лимит — это партиальность, и она обязана быть объявлена**) и R1-C37 (**проверка,
которой ни разу не показали то, что она обязана отвергнуть, — не проверка**): здесь правилу нечего
показать в принципе, а гейт об этом молчит. Практическое последствие: переименуйте слой, забудьте
`codemap.toml` — гейт продолжает печатать ✅ и считать это правило выполненным.

## 2. D1 — применимость считается и объявляется, семантика не меняется

**Решение: у каждого правила есть два числа — *declared* и *applicable*, и они попадают в ответ, когда
различаются.**

Применимость определяется по одному признаку: **имя, названное в правиле, присутствует среди слоёв
графа**. Для `layers` — сам слой; для `independent` — группа применима, если существуют **хотя бы два**
её члена (одного мало: «не импортировать друг друга» требует двух); для `forbidden` — существуют **оба**
конца.

**Когда всё объявленное существует, вывод не меняется ни на байт.** Это одновременно и контроль
(здоровый контракт не двигается — важно для потребителей, которые диффают текст), и правило R1-C28
наоборот: метка появляется там, где есть о чём сообщить. Отсутствие расхождения и есть сообщение
«расхождения нет», потому что числа печатаются в одном и том же формате.

- **Отвергнуто: считать применимость всегда и печатать `layered (7 declared, 7 applicable)` даже когда
  они равны.** Формально честнее, а на практике это шум в каждом зелёном прогоне и изменение текста у
  всех потребителей ради нуля информации. Сообщение о партиальности должно быть там, где партиальность
  есть.
- **Отвергнуто: молча не считать фантомные правила в счёте** (печатать `layered (5)` вместо
  `layered (7)`). Тогда читатель не отличит «я объявил 7, работают 5» от «я объявил 5», а это разные
  положения дел — та же ошибка, что «пустой ответ, не сказавший, какого рода пустота» (R1-C44).

## 3. D2 — превращать фантом в нарушение можно только по просьбе

**Решение: `no_phantom_rules = false` по умолчанию; `true` делает фантомное имя нарушением.**

Имя в семье `no_cycles` / `no_lazy_cycles` / `no_type_only_cycles` выбрано нарочно: это такой же
опциональный гейт, включаемый владельцем контракта, а не дефолт, выбранный за него.

- **Отвергнуто: падать всегда.** Сломает контракты, написанные вперёд кода, — а это документированное
  свойство (§1). Ужесточение по умолчанию здесь хуже болезни: оно превращает легальную практику в
  красный CI на чужих деревьях при обновлении инструмента.
- **Отвергнуто: расширить `exhaustive`.** `exhaustive` отвечает на обратный вопрос — «каждый слой кода
  объявлен ли в контракте». Склеить два направления в один флаг значит лишить владельца возможности
  включить одно без другого, а они независимы: у bquant `exhaustive = true` и фантомов нет.

## 4. D3 — это правится в одном месте, а не в рендерере

Счёт живёт в `arch.py`, показывают его **два** потребителя: markdown (`render_check`) и структурный
ответ (`build_check`), который читают гейт лаборатории и MCP-инструмент. Починка только в markdown
оставила бы ложное число в машинном ответе — ровно та ошибка, которую R1-C51 и issue #20 уже стоили:
лечить у потребителя, на которого указал репорт, вместо источника.

## 5. Приёмка — замерено 0.0.20 из PyPI против нового кода на одних и тех же графах

| проверка | 0.0.20 | после |
|---|---|---|
| фикстура, контракт из трёх вымышленных слоёв | `✅ layered (3), independent (1), forbidden (1), no_cycles`, exit 0 | `✅ layered (3 declared, 0 applicable), independent (1 declared, 0 applicable), forbidden (1 declared, 0 applicable), no_cycles` + строка с именами `frontend`, `middleware`, `persistence`, exit 0 ✅ |
| та же фикстура + `no_phantom_rules = true` | флага не знает: `✅ …`, exit 0 | `❌ no_phantom_rules — 3 name(s) … absent from the graph`, три имени списком, **exit 2** ✅ |
| **фикстура со здоровым контрактом** | — | вывод **побайтово идентичен** 0.0.20 (`cmp`) ✅ |
| **живое дерево bquant, их настоящий контракт** (7 слоёв, все существуют, `exhaustive = true`) | `✅ layered (7), forbidden (8), no_cycles, no_type_only_cycles, exhaustive`, exit 0 | **побайтово идентично**, exit 0 ✅ |

Последние две строки — контроль обещания D1 и главный факт для потребителей: **у дерева без
фантомов не меняется ни один байт вывода**. Это отличает эту правку от 0.0.20, где форма вывода
поехала у всех.

**Сторожа:** `tests/test_r1c62_phantom_rules.py`, 11 тестов; сьют 972 → 983. Мутационно: выключение
раскрытия роняет 2, удаление опт-ина — 2, выброс `applicability` из структурного ответа — 2; пять
остальных положительные контроли (здоровый контракт не двигается, точность применимости на частично
существующих именах, выключено по умолчанию, настоящее нарушение срабатывает рядом с фантомами,
опт-ин молчит на здоровом контракте).

## 6. Чего это не покрывает

- **Правило с именем не того рода.** `forbidden = [{ from = "pkg.gone", to = "pkg.core" }]` называет
  модули, а не слои, и не сработает никогда — даже если модули существуют. Эта проверка ловит его лишь
  постольку, поскольку `pkg.gone` не является именем слоя; сказать «вы перепутали словарь» она не умеет.
- **Слой, который существует, но у которого не бывает рёбер.** Применимость — про наличие имени, а не
  про возможность нарушения. Правило про два существующих слоя, между которыми импорт невозможен по
  смыслу, остаётся необнаружимым и не должно обнаруживаться.
- **Устаревание прозы.** Дизайн-записи, «чего это не покрывает» и правила в `AGENTS.md` этим не
  проверяются никак; механически проверяется структура, а не смысл.
- **Не трогает семантику.** Фантомные правила по-прежнему инертны, и контракт по-прежнему можно писать
  вперёд кода.
