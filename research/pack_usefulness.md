# Полезность `pack`, V2 — оракул по истории коммитов

**R1-C61.** Предрегистрация записана и закоммичена **до** прогона по 108 коммитам; сверка — ниже, после
прогона. Харнесс: [`bench/pack_usefulness.py`](bench/pack_usefulness.py).

## 0. Вопрос и почему так

`pack` проверен на детерминизм и на бюджет, но не на то, **указывает ли он туда, где идёт работа**. Все
прежние «эталоны» бенча — граф самого codemap, и сравнение с ним замкнуто на себя (пост 10). Здесь эталон —
**git**: если коммит изменил файл пакета, то другие файлы, изменённые тем же коммитом, — это файлы, которые
понадобились человеку для этой правки. Граф строится на **родителе** коммита, так что ни один метод не видит
саму правку.

Это не «агент решает задачу лучше» (V4, платный и невоспроизводимый). Это дешёвый вопрос, который решает,
имеет ли смысл платить за V4: **если `pack` не обгоняет grep по именам и `impact`, мерить агента нечего.**

Предусловие выполнено: R1-C65 (`docs/design/pack_honesty.md`) — затравка, которая ни во что не раскрылась,
теперь отказ, а не молчаливый глобальный пакет, и недостижимое в пакет не попадает.

## 1. Отбор — фиксирован

- Репозиторий: bquant (публичный), ref **закреплён**: `40839156608c6324d41290b17fb9f8d8322f4f59` — `HEAD`
  движется (его ведёт другая сессия), а замер против движущейся мишени меряет мишень (R1-C25).
- Коммиты без слияний, достижимые из ref; хотя бы один **изменённый** `.py` в `bquant/`; от 2 до 15
  изменённых-или-удалённых `.py` в корнях кода (`bquant/ tests/ examples/ scripts/ research/`).
- **Затравка** — изменённый файл пакета с наибольшим числом изменённых строк (равенство → путь).
- **Эталон** — остальные изменённые-или-удалённые `.py` в корнях кода. Добавленные (у родителя их нет) и
  переименованные исключены и посчитаны; `.md` исключены и посчитаны — пакет не может содержать документ по
  построению (R1-C65 это объявляет), так что включать их значило бы мерить объявленное.
- Результат отбора: **108 коммитов**, sha256 списка хэшей
  `2197505e653ad6ae55e803f71719893ea177aaebd6e6b7692583945bb2e98ebe`. Размер эталона: 1 файл — 24
  коммита, 2 — 14, 3 — 20, 4 — 10, 5 — 14, 6–13 — 26. Корни эталона: bquant 259, tests 96, research 51,
  examples 34, scripts 1. Исключено: 169 добавленных `.py`, 43 переименования, **549 `.md`**.
- **Берутся все 108**, без выборки. N фиксирован, промежуточных подглядываний нет, публикуется любой исход.

## 2. Методы — у всех одна затравка, один кандидатный набор, один K

| метод | что это |
|---|---|
| `pack` | `build_pack(seeds=(seed_file,))`, элементы по рангу → файлы |
| `pack_global` | `build_pack()` без затравки → файлы (только «важность») |
| `impact` | `impact(<модуль затравки>, depth=2)` → файлы по расстоянию, затем путь |
| `impact+pack` | поочерёдно `impact` и `pack`, `impact` первым, без повторов |
| `grep` | файлы, где встречается имя любой функции/класса верхнего уровня затравки или её точечный путь модуля; по числу совпадений, затем путь |
| `random` | кандидаты, перемешанные с сидом от хэша коммита |

Граф: быстрый уровень, repo-scope (`bquant` + потребители `tests examples scripts research`, какие есть у
родителя), без документов. **Глубокий уровень не мерится** — 108 сборок по ~2 мин; объявлено как
ограничение.

Метрики: recall@5/10/20 (доля эталона в первых K), hit@10 (хоть один из эталона в первых 10), recall@10
только по файлам `tests/` эталона, и попарные победы по recall@10 (лучше / хуже / равно).

## 3. Контроли

| # | контроль | опровергается |
|---|---|---|
| **C1** | отбор и его хэш закоммичены до прогона; ref закреплён | иной хэш при прогоне |
| **C2** | граф строится у **родителя**; провалы сборки посчитаны. **Стоп**, если провалов > 20 % | > 21 провала |
| **C3** | затравка каждого коммита раскрывается (`via: file`); отказы посчитаны. **Стоп**, если > 20 % | > 21 отказа |
| **C4** | детерминизм: 5 коммитов прогоняются дважды, результаты побайтово равны | любое расхождение |
| **C5** | `random` хуже каждого метода по recall@10 — иначе прибор сломан | метод не обгоняет случайный |

## 4. Предсказания — каждое может провалиться

| # | предсказание | опровергается |
|---|---|---|
| **P1** | затравка помогает: `pack` обгоняет `pack_global` по среднему recall@10 на **≥ 0.10** | разница < 0.10 |
| **P2** | `pack` **не** обгоняет `grep`: recall@10 `pack` ≤ `grep` + 0.05 | `pack` выше `grep` больше чем на 0.05 |
| **P3** | `impact` обгоняет `pack` на **≥ 0.10** по recall@10 — правка тянет за собой тех, кто *использует* изменённое, а `pack` идёт в обратную сторону | разница < 0.10 |
| **P4** | `pack` почти не находит тесты: recall@10 по `tests/` эталона **< 0.05** — тесты используют затравку, а не наоборот, и в пакет с затравкой не попадают по построению | ≥ 0.05 |
| **P5** | `pack` всё же что-то добавляет к `impact`: `impact+pack` обгоняет `impact` на **≥ 0.03** по recall@10 | разница < 0.03 |

Если ничего не сделано (прибор не работает), C5 и P1 проваливаются. Если `pack` хорош, проваливаются P2,
P3, P4.

## 5. Чего это не покажет

- **Помогает ли пакет агенту.** «Изменено тем же коммитом» ≠ «нужно было прочитать», и коммит ≠ задача.
- **Другие деревья.** Один репозиторий, его стиль коммитов (в bquant правка часто идёт вместе с тестами и
  трейс-логом).
- **Глубокий уровень** и бюджет: `pack` берётся без ограничения бюджета (порядок важнее объёма), `grep` — по
  именам верхнего уровня, без методов классов.
- **Документы.** Исключены из эталона по построению; полнота по ним у `pack` — ноль, и это объявлено, а не
  измерено.
