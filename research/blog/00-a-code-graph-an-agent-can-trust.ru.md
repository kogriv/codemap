# Граф кода, которому агент может доверять

*У агента, работающего в коде, есть два плохих варианта: grep (точный, но слепой к структуре) и эмбеддинги (нечёткие и вечно протухшие). Третий путь — точный структурный граф — раз за разом выходил непрозрачным индексом, который гниёт на следующем коммите. codemap — это тот самый третий путь, только diffable.*

> **Граф кода, которому агент может доверять: только исходники, детерминированный, diffable
> — нет индекса, который протухнет, нет LSP, который надо поднимать.**

Это лончевый пост серии про **[codemap](https://github.com/kogriv/codemap)** — инструмент с
открытым кодом (MIT), который я разрабатываю. Остальная серия — полевые заметки: разборы
конкурирующих инструментов, измеренные в очных ставках, по одному честному сюрпризу за раз.
А этот пост про *почему*: что такое codemap, на какую ставку он идёт и где сидит в тесном
поле.

## Зуд

У ИИ-агента, работающего в кодовой базе, есть два накатанных варианта, и оба плохи вполне
конкретным образом.

**grep** точен и мгновенен — и совершенно слеп к структуре. Он найдёт строку
`MACDZoneAnalyzer`, но не скажет, *кто её вызывает*, *что сломается, если поменять её
сигнатуру*, и *какие из этих совпадений в ядре, а какие в тестах*. Он матчит текст; он не
понимает код.

**Эмбеддинги / RAG** понимают *смысл* — спроси «где логика определения свингов», и векторный
поиск найдёт её, не зная имени. Но ответ нечёткий, недетерминированный (запусти дважды —
получи два ранжирования) и **вечно протухший**: индекс отражает репозиторий таким, каким он
был в момент эмбеддинга, а код меняется каждый коммит. Ты поднимаешь модель, ждёшь прогон
эмбеддинга — и всё равно получаешь вероятностный ответ на вопрос, у которого часто есть
точный.

Есть очевидный третий путь: **точный структурный граф** — настоящие узлы и рёбра, *эта
функция вызывает ту*, разрешённые. Беда в том, как его раз за разом строили: как
непрозрачный, не-diffable индекс (LSIF, вендорские базы), который гниёт в момент изменения
кода и который нельзя отревьюить в пул-реквесте. Точность была настоящей; а вот *артефакт*
был чёрным ящиком.

## Ставка

codemap идёт третьим путём и чинит артефакт. Четыре обязательства:

- **Только исходники.** Он читает исходники через griffe и jedi — без компиляции, без venv,
  без импорта в рантайме. Работает на любом пакете, на любой машине, офлайн, и остаётся
  полностью развязанным с кодом, который анализирует. Нет языкового сервера, который надо
  поднимать (и, как выяснится, [самый первый пост серии](01-the-competitor-wasnt-broken.ru.md) — как раз про это решение).
- **Канонический и diffable.** Артефакт — один `graph.json`: отсортированный, без
  таймстампов, байт-стабильный между прогонами. Граф, который можно `git diff`. Закоммить его
  в репозиторий — и структурное изменение всплывёт в код-ревью, как любой другой diff.
- **С учётом происхождения.** Каждый узел знает, откуда он: ядро пакета, тесты,
  документация, примеры, скрипты. Так у вопроса «что сломается, если я это поменяю?»
  появляется ответ *лучше* плоского счётчика: 2 ссылки в ядре, 7 в документации, 53 в
  тестах. Это различие — граница между «это несущее» и «это хорошо покрыто».
- **Родной для агента.** Граф выставлен как глаголы, которые агент вызывает через MCP —
  `impact`, `callers`, `callees`, `architecture`, `review`, — а не как язык запросов, который
  надо учить.

## Арка, в четырёх движениях

codemap рос публично примерно за двадцать вех. Сжато:

1. **Граф существует.** Каноническая структура (импорты / экспорты / наследование), API
   запросов, поведенческий граф вызовов, глубокое разрешение вызовов через jedi и
   рендер-виды (RAG-чанки, хранилище Obsidian, mermaid). Фундамент: детерминированный граф из
   чистых исходников.
2. **Граф обретает мнение.** Мультикорневое **происхождение** и impact/радиус поражения;
   мост вызовов с учётом реестров; **dead-code с учётом происхождения** (польза vulture без
   его главного источника ложных срабатываний); контракты аргументов на каждое место вызова;
   dataflow по строковым ключам-колонкам. Здесь он перестаёт быть деревом разбора и начинает
   отвечать на настоящие вопросы.
3. **Эргономика и высота.** Обнаружение (search / families / source / resolve);
   обоснованность (неоднозначность *выносится наружу*, а не разрешается молча);
   **change-review** (diff → досье, отсортированное по риску); **архитектурный** вид (слои,
   связность, god-объекты, циклы).
4. **Родной для агента и честный про время.** **MCP-адаптер** (граф как инструменты агента);
   и **свежесть** — статический граф теперь сообщает свой возраст, говорит, когда он отстал
   от кода, пересобирает только изменившиеся модули (~×12 быстрее на правке одного файла) и
   может быть перезагружен в работающий сервер без рестарта. Детерминизм сохранён тем, что
   рецепт сборки лежит в сайдкаре, а не в самом графе.

Где он сегодня: схема **0.11**, ~**369 тестов** зелёные, тёплая serve-поверхность из
**29 операций** (26 из них — как MCP-инструменты), плюс **экспорт SCIP**, чтобы
Sourcegraph / Glean и другие инструменты точной кодовой аналитики зажигались поверх графа
codemap. Он взаимодействует наружу, а не запирает свой граф.

## Где он сидит в поле

Я не хотел *заявлять* нишу — я хотел *измериться* в неё. Поэтому исследовательский трек
серии поставил codemap против каждого соседнего инструмента по одним осям. Недообслуженное
место, куда он приземлился: **семантический (разрешённый) граф кода**, который одновременно
**детерминирован**, **только-исходники**, **глубок по Python** и **обращён к агенту**.
Соседи каждый промахиваются по одной оси — эмбеддинг-инструменты недетерминированы; ctags и
LSIF не разрешённые; языковой сервер эфемерен; тяжёлые графовые базы (Kythe, Glean) требуют
компилятор. Никто из них не *неправ*; они играют в соседние игры. Ставка codemap — владеть
этим одним пересечением и взаимодействовать с остальными.

## Честная часть

Лончевому посту, который только льстит, не верят — как и графу. Настоящие ограничения:

- **Нет разрешения через границу — внутрь зависимостей.** codemap — только-исходники
  *таргета*; он не скажет, какой API pandas дёргает вызов. Некоторые инструменты умеют — по
  замыслу, но это реальный предел. (Первый разбор серии как раз про один из таких
  инструментов.)
- **Только Python.** Соседи, охватывающие дюжину языков, покупают эту ширину, опираясь на
  tree-sitter или LSP. Глубина codemap куплена Python-специфичностью. Осознанный размен, а не
  недосмотр.
- **У глубокого разрешения есть разброс.** Глубокий слой на jedi ограничен и чувствителен к
  кэшу; две полные глубокие сборки могут отличаться на пару рёбер. Быстрый/структурный слои
  полностью детерминированы — и именно на этом слое держится заявление про «diffable».

## Попробуйте — и поймайте меня на ошибке

```bash
pip install codmap         # имя дистрибутива; команда и импорт — `codemap`
codemap build ./yourpkg --deep -o graph.json
codemap serve --graph graph.json            # тёплый процесс, JSON по stdin/stdout
codemap serve --graph graph.json --mcp      # …или как MCP-инструменты для агента
```

Следующие посты становятся конкретными и состязательными: я гоняю codemap против ближайших
конкурентов на общем таргете, меряю по пять вопросов на каждого и рассказываю сюрпризы — в
том числе тот, где я чуть не опубликовал, что конкурент сломан, а оказалось — это была моя
собственная ошибка.
